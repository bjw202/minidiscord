# minidiscord — 제품 개요

> 설계 원문: `.moai/plan/2026-08-26-minidiscord/spec-v2.md`, `plan-v2.md` (v1 문서는 대조용으로 보존)

## 무엇을 만드는가

minidiscord는 회사 네트워크 등 디스코드를 쓸 수 없는 환경에서, 클로드코드 세션을 봇으로
참여시켜 대화할 수 있는 **자체 호스팅 채팅 서버**다. 디스코드의 역할을 대신한다고 보면 된다.

Claude Code는 공식 Channels 기능으로 클로드코드 세션을 디스코드·텔레그램 같은 메신저에 봇으로
접속시킬 수 있다. 하지만 이 프로젝트의 사용자는 회사에서 디스코드를 쓸 수 없어 이 기능을
그대로 활용하지 못한다. minidiscord는 "사내망·과제원에서 쓸 나만의 디스코드"를 만들어 이 문제를
해결한다 — 배치 목표는 사내망·과제원이고, 서버의 기본 바인드는 지금도 `127.0.0.1`이라
지금은 이 PC에서만 접속된다.

## 왜 필요한가 (배경)

- 사용자는 항상 켜져 있어 서버를 띄워 둘 수 있는 PC를 가지고 있다.
- 그 PC에서 minidiscord 서버를 띄워두면, 사용자는 회사 PC를 포함해 어디서든 브라우저로
  `http://<내PC주소>:3000`에 접속해 자신의 클로드코드 세션들과 대화할 수 있다.
- 클로드코드 세션은 공식 Channels 계약을 구현한 **커스텀 채널 플러그인**을 통해 이 서버에
  봇으로 참여한다.

```
브라우저(회사 PC 등) ──HTTP/SSE──▶ minidiscord 서버(사내망·과제원) ◀──WebSocket── 채널 플러그인 ◀──stdio(MCP)── Claude Code 세션들
```

## 성공 기준

1. 방을 만들고 봇을 초대(세션 접속)해 대화가 오간다.
2. 긴 대화가 서버 재시작·브라우저 재접속 후에도 그대로 남아 있다.
3. 파일을 올리고 받을 수 있다(사람↔봇 양방향).
4. 한 방에 여러 봇이 동시에 접속해 각자 독립적으로 답변한다.
5. `@TO`/`@CC` 멘션으로 누가 답할지 제어한다.
6. 봇이 세션을 초기화(`clear`)했어도 스스로 대화 기록을 다시 가져올 수 있고, 멘션 없이 오간 대화도 `since_id` 커서로 따라잡을 수 있다.

## 기능 요구사항

| 영역 | 내용 |
|---|---|
| **계정** | 소수 그룹이 각자 계정으로 로그인한다. 방별 접근 권한 통제는 두지 않는다(YAGNI). |
| **방** | 대화방을 만들고 이름을 붙인다. 프로젝트(과제)마다 방을 새로 만드는 것을 기본 사용 패턴으로 삼는다. |
| **방 보관** | 방을 닫으면(archive) 대화·파일은 읽기 전용으로 보존되고, 그 방의 봇 토큰이 일괄 무효화되어 채널 접속이 끊긴다. 새 메시지는 금지된다. 사이드바에서 보관된 방은 접어서 보여준다. |
| **봇 등록/초대** | 봇 정의(이름, 설명)를 전역으로 등록한다. 방에서 봇을 초대하면 (방, 봇) 조합의 접속 토큰이 발급되고, 세션 실행 명령 안내가 화면에 표시된다. 사용자가 원하는 페르소나 디렉터리에서 그 명령으로 세션을 띄우면 봇이 온라인으로 표시된다. |
| **메시지** | 방에서 긴 대화를 나눈다. 접속 전에 오간 메시지를 포함해 전부 서버 DB에 저장되고, 이후 접속한 봇도 이를 불러올 수 있다. |
| **@TO/@CC 라우팅** | `@TO(봇)`은 지정 봇에게 직접 전달하고 응답을 의무로 한다. `@CC(봇)`은 전달만 하고 응답을 금지한다. 멘션이 없는 메시지는 어느 봇에게도 전달되지 않는다. 한 메시지에 여러 멘션을 섞어 쓸 수 있다. 입력창에는 봇 이름 자동완성이 붙는다. |
| **파일** | 사람은 파일을 업로드/다운로드할 수 있고, 봇은 첨부 파일을 발신하고 업로드된 파일을 읽을 수 있다. |
| **권한 릴레이** | 봇이 도구 사용 승인이 필요하면 방에 승인 요청 메시지가 뜨고, 사람이 방에서 직접 승인/거절할 수 있다. |
| **기록 조회** | 봇은 `fetch_history` 도구로 방의 대화 기록을(전체/부분/발화자별) 스스로 가져올 수 있다. 조회 결과의 각 줄에는 메시지 번호(`#번호`)가 붙고, `since_id`로 "그 번호 다음부터"만 요청할 수 있다. 멘션 없이 오간 대화를 따라잡거나 세션이 초기화(clear)된 뒤 맥락을 복구하는 데 쓰는 유일한 경로다. |
| **봇 상태** | 각 봇의 온라인/오프라인, "입력 중" 상태가 방 화면에 표시된다. |

## 비기능 요구사항

- **구현 언어/런타임**: Node.js + TypeScript.
- **프로세스 구조**: 단일 서버 프로세스(멀티 프로세스/분산 구조 없음).
- **저장소**: SQLite 하나로 모든 영속 데이터를 관리한다.
- **응답 방식**: 봇 응답은 완성된 답변을 한 번에 보내는 방식이며, 스트리밍 응답은 지원하지 않는다.
- **통신/인증**: HTTP + 단순 로그인(계정/비밀번호, 세션 쿠키)으로 시작한다. HTTPS는 이후 업그레이드
  경로로만 남겨두고 v1 범위에는 포함하지 않는다.
