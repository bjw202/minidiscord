## 0. 이번 라운드의 방법

2회차 판정이 지목한 것은 결함 열 건이 아니라 **결함의 형태 하나**였다 — 1회차 교정이 본체를 고치고 그 본체를 참조·측정하는 자리를 따라가지 않았다. 그래서 이번에는 정정마다 아래 **네 부류를 편집 전에 열거하고 전부 훑었다.**

1. **진술** — 그 사실을 말하는 자리
2. **재진술** — 요약·위험표·§E·이력행·`progress.md`·`plan.md` §B/§E/§G 등 다시 말하는 자리
3. **측정** — 그 사실을 재는 기준·변이표 행·전이 단계
4. **형제 참조** — 다른 SPEC 이 그것을 가리키는 자리

아래 표의 **정정** 행은 각각 네 부류를 어디까지 훑었고 무엇이 나왔는지를 적는다.

## 2. 판단이 필요했던 자리 — 운영자 확인 요청

**형제 `SPEC-CHANPERM-001/acceptance.md:339` 의 설명 문장 하나를 고쳤다.** 운영자 지시 4는 "형제 SPEC 은 t9 게이트·표기 정리에만 손대고 기준 본문 추가 개정은 하지 말 것"이었다. 이 편집은 **기준 본문을 한 글자도 바꾸지 않는다** — `it` 블록, 두 단언, 통과 조건이 전부 그대로이고, `**Then**` 뒤 설명 문장만 사실에 맞게 고쳤다(N-9 가 지목한 그 문장이 `SPEC-CHANAUTH-001` AC-007 과 **글자만 다른 같은 과잉 주장**이었다). 지시의 "표기 정리" 범위로 읽었으나, 다르게 읽으신다면 이 한 줄만 되돌리면 된다 — 다른 정정과 얽혀 있지 않다.

## 3. 미검증 (Gaps)

**통과로 읽어서는 안 되는 것들이다.**

1. **테스트 실행 결과 전부.** `node_modules` 가 없어 `npm test -w channel` 을 **한 번도 실행하지 않았다.** N-6 의 "A 는 넷을 무너뜨린다", N-7 의 "루프 교정으로 5,000ms 안에 든다", N-8 의 "순서 보존이므로 기다릴 필요가 없다"는 전부 **소스 대조 판정**이며 실행 관측이 아니다.
2. **N-7 교정 후의 실제 소요 시간.** 루프에서 6,450ms 를 걷어냈다는 것은 산술이고, `handlePermissionVerdict` 3회의 `tick()`(150ms)과 129건 처리 자체의 비용은 재지 못했다. 여유는 크지만 관측은 아니다.
3. **변이 C 의 실패 집합.** `throw` 가 `ws` 의 message 리스너에서 어떻게 전파되는지에 따라 AC-003 (나)의 성패가 갈린다. 표에 "함께 실패할 수 있다"로 적고 run 단계 실측에 넘겼다 — **확정하지 못한 유일한 변이 행이다.**
4. **`helloAgain()` 의 실제 동작.** 같은 소켓 위 `welcome` 재전송이 클라이언트 상태를 뒤집는지는 구현이 없으므로 확인 불가. AC-003 (나) 전체가 이 전제 위에 있다(2회차 감사 Gap 3 과 동일 — 해소되지 않았다).
5. **`AC-CHANNEL-004 (b)`·`005 (b)` 의 vitest 짝 존재.** 그 SPEC 문서가 "(b) vitest 회귀층"이라 적은 것을 읽어 확인했고, `channel/test/` 에서 대응 `it` 을 일일이 대조하지는 않았다.
6. **`AC-CHANPERM-001..010`·`AC-CHANCLIENT-001..014` 가 전부 vitest 기준이라는 것.** 각 SPEC 의 011/012·015/016 이 셸·전이 기준임은 절 제목으로 직접 확인했으나, 나머지 24건을 한 건씩 열어 확인하지는 않았다.
7. **커버리지·타입 검사·lint.** 실행 불가.

## 4. run 단계 잔여 위험

- **변이 C 의 집합이 표와 어긋날 때의 처리.** 이번 라운드가 유일하게 열어 둔 판단 자리다. 표 아래 주가 "실측한 집합을 원문으로 남기고 판정한 뒤 진행"으로 절차를 못 박았고, H-01·N-6 교정을 되돌리지 말라는 금지도 함께 적었다. 그래도 여기는 run 단계가 문서를 고치고 싶어지는 자리이므로, 어긋나면 **고치지 말고 보고**하는 편이 안전하다.
- **전이 1b 와 전이 5 는 «건수»가 판정 기준이다.** 일곱 건·다섯 건이 아니면 멈추고 보고하도록 두 문서 모두에 적었다. 이 숫자는 계획 단계의 **소스 대조 예측**이지 실측이 아니므로 어긋나는 것 자체가 결함이 아닐 수 있다 — 다만 그 차이를 설명하지 않고 넘어가면 계약 충돌의 증거가 흐려진다.
- **`AC-CHANNEL-002` 셸 프로브가 회귀 스위트 밖에 있다.** 이 카드가 그 사실을 명시적으로 적었으나 구조는 그대로다 — `.moai/reports/t4/sync-audit.md` §3.2 가 지목한 부류가 형제 SPEC 쪽에 남아 있다는 뜻이며, 이 카드의 범위 밖이다.
- **N-7 교정이 형제 하네스와 다른 형태를 만든다.** AC-009 만 `sendRequest` 를 쓰지 않으므로, 나중에 누군가 "일관성"을 이유로 되돌리면 타임아웃이 조용히 되살아난다. 기준 본문에 되돌리지 말아야 할 이유를 적어 두었다.
