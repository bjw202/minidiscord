## 2. 반드시 판정할 것 ② — D-01 부분 반박은 **타당하다 (감사관이 틀렸다)**

개정자가 내 1회차 처방(`recordSocket` 으로 재라)을 거부했다. **그 반박은 옳고, 내 처방이 틀렸다.** 실측으로 확인한다.

```
$ grep -n "onConnection" server/src/gateway.ts
85:// onConnection: 하네스가 서버 쪽 소켓을 관측하는 유일한 창구 (SPEC-GWAUTH-002 acceptance.md §「서버
87:export function createGateway(app: FastifyInstance, opts: { uploadsDir: string; botFilesDir?: string; onConnection?: (ws: WebSocket) => void }): Gateway {
103:    opts.onConnection?.(ws)

$ grep -n "createGateway" server/src/index.ts
47:  const gateway = createGateway(app, { uploadsDir: config.uploadsDir, botFilesDir: config.botFilesDir })

$ sed -n '100,110p' server/test/gateway-v2.ts
export function recordSocket(ws: WebSocket): { … }
  const orig = ws.send.bind(ws) as …
  ;(ws as unknown as { send: … }).send = (data, cb) => {   ← 서버 쪽 소켓의 send 를 교체
```

세 사실이 반박을 세운다:

1. `recordSocket(ws)` 은 **서버 쪽 `WebSocket` 객체의 `send` 를 몽키패치**한다(`gateway-v2.ts:108-113`). 클라이언트 소켓이 아니다.
2. 그 객체는 `createGateway` 의 `onConnection` 콜백으로만 나오고, 주석(`:85`)이 스스로 «유일한 창구»라고 못박는다.
3. **`server/src/index.ts:47` 은 `onConnection` 을 넘기지 않는다** — 축자 확인. 그리고 E2E 는 서버를 **별도 프로세스**로 띄운다(REQ-E2E-001).

따라서 별도 프로세스의 소켓 객체를 감쌀 방법은 없다. **1회차 §8 우선순위 2 의 처방은 구조적으로 실행 불가능한 것이었고, 개정자가 그것을 실측으로 잡아냈다.** 반박을 전건 수용한다.

### 대체 기제도 D-01 을 실제로 닫는가 — **닫는다**

`acceptance.md:24-35` 의 새 AC-E2E-002 는 소스 grep 을 버리고 동작을 잰다.

- **양성(㉠)**: `[5/15]` 표지. `connectV2` 는 `server_proof` 를 `timingSafeEqual` 로 대조하고(`gateway-v2.ts:45-46`) 봉투 `mac`·`seq` 를 검증한 뒤(`:67-70`)에만 해소하므로, 표지가 찍혔다는 것은 v2 가 실제로 성립했다는 뜻이다. **소스 문자열이 아니라 전선의 사실이다.**
- **음성 대조군(㉡)**: `[6/15]` 표지 + 「close 까지 수신 프레임 0건」. 근거를 실측했다:
  ```
  $ sed -n '118,122p' server/src/gateway.ts
    function dropConn(ws: WebSocket): void {
      handshakes.delete(ws)
      conns.delete(ws)
      ws.close()
    }
  ```
  **`send` 호출이 없다** — 서버는 v1 소켓에 아무것도 보내지 않고 닫는다. 「0건 수신」은 추론이 아니라 코드가 보증하는 관측이다.
- **공유 하네스 미편집**: 두 측정 모두 `scripts/e2e.mts` 안에서 이뤄진다(`acceptance.md:35`, `plan.md:98`). 1회차의 두 번째 지적(「변이가 지나치게 굵다」)도 함께 닫혔다.
- **재지 않는 것을 스스로 적었다**: `acceptance.md:34` — 「`gateway.ts:191` 의 auth 서명 검증을 지워도 ㉠ 은 통과하므로 이 기준은 그 층을 재지 않는다(그 층은 `SPEC-GWAUTH-002` 소유)」. **기준이 자기 사각지대를 명시하는 것은 이 프로젝트에서 드문 좋은 형태다.**

## 12. 검증하지 않은 것 (Gaps)

- **[실행 불가] 아무 명령도 돌리지 못했다 — E2E 도, 서버도, vitest 도.** `ls node_modules` → `No such file or directory`; `ls -d server/node_modules` → 없음. 따라서 `npm run e2e`·`npm test`·`npx vitest run` 을 **한 번도 실행하지 않았다.** 이 감사는 1회차와 마찬가지로 **전부 정적 판독 + 읽기 전용 grep/sed** 다.
- **[실행 불가] 새 기준의 측정 명령을 실제로 돌려보지 못했다** — AC-E2E-006 의 `exit=9`, AC-E2E-007 의 `[1/15]…[15/15]`, AC-E2E-009 의 `npx vitest run --root server restart-persistence` 는 전부 아직 존재하지 않는 산출물을 겨눈다. 사전 상태만 쟀다.
- **[실행함] `git diff` 계열은 읽기 전용이라 돌렸다** — N-01 의 `unset BASE` 실험은 실제 실행 결과다(`exit=0`, 빈 출력).
- **`openDb(':memory:')` 변이를 돌리지 않았다** — 1회차 D-15 의 미검증이 그대로 남는다. SPEC 은 그 구분을 run 단계 변이표에 기록하게 했을 뿐이다.
- **`scripts/e2e.mts` → `../server/test/gateway-v2.ts` 의 `tsx` 해소를 실행 확인하지 않았다** — D1(a) 채택의 잔여 위험. `plan.md` §C 가 처음 잰다.
- **음성 대조군이 실제로 「프레임 0건 후 close」로 관측되는지 돌려보지 않았다** — `dropConn`(`gateway.ts:118-122`)에 `send` 가 없음을 **코드로** 확인했을 뿐, `ws` 라이브러리가 close 프레임 외에 무엇을 이벤트로 올리는지는 실행으로 재지 않았다. 개정자도 같은 Gap 을 선언했다(`plan-revision-1.md:301`) — **정직한 자기 공시다.**
- **정본 `proposal.md` 를 이번에도 읽지 않았다.** 코디네이터가 소유권 판정을 범위 밖으로 명시했고, 정본이 이 나무에 없어(미추적 산출물) 절대 경로 접근이 필요했다. **따라서 `spec.md:118` 의 정본 인용(§5 마지막 문장)이 축자로 정확한지 검증하지 못했다** — 개정자의 인용을 그대로 받았다. 이것이 이번 회차의 최대 미검증이며, 소유권 결정이 그 인용 위에 서 있으므로 **리드가 직접 대조할 것을 권한다.**
- **README 갱신 후 상태는 재지 않았다** — 모든 「갱신 후 기대」는 예측이다. 사전 상태만 실측했다.
- **1회차에 통과한 자리는 재검증하지 않았다** — 재감사 계약대로 델타 범위를 지켰다. 따라서 v0.1.0 에서 문제없던 부분이 개정으로 깨졌을 가능성은 D-01~D-16 이 닿는 자리 밖에서는 배제하지 못한다.
