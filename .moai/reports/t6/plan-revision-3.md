## 0. 쉬운 말 요약

3회차 감사는 여유 있는 합격(0.911)을 줬고, 남은 지적은 **증거를 적는 방식** 하나에 몰려 있었습니다. 핵심은 이렇습니다 — 제가 「낡은 값이 남았는지 훑는 표」를 만들었는데, **그 표가 자기 자신을 세고 있었습니다.** 표에 적힌 명령을 그대로 돌리면 표에 적힌 숫자가 나오지 않았습니다.

지난 라운드에서 이미 같은 문제를 **값 축에서는** 풀어 놨었습니다(검사 범위를 실행 명령 줄로 좁혀서). 그런데 이번에 새로 더한 **명제 축**에는 그 처방을 적용하지 않았습니다. 리드 지시대로 **숫자를 고치는 대신 같은 처방을 적용**했습니다 — 표의 자기 적중 줄에 표지를 달고, 명령이 그 표지를 빼도록 했습니다.

작업 중 **또 하나를 스스로 밟았습니다.** 표에 「이 세 줄이다」라고 줄 번호를 박아 뒀는데, **이번 라운드가 이력 한 줄을 추가하자 그 번호들이 전부 한 칸씩 밀려 즉시 거짓이 됐습니다.** 줄 번호 대신 문구로 가리키도록 고쳤고, 왜 그래야 하는지도 적었습니다.

## 2. P-01 · P-03 — 표가 자기를 센다 (같은 뿌리, 함께 처리)

### 감사 주장 재현

```
$ grep -n "종결 정의\|종결 조건" spec.md | wc -l
6            ← SPEC 은 3 이라 적었다
```
적중 여섯 중 **뒤 셋이 §7.3 표 자신**이었다(행6·행7·요약 문장). 그리고 판정 열의 열거 「3번 항목」은 그 줄에 해당 문자열이 없어 **거짓**이었다:
```
$ sed -n '51p' spec.md | grep -c '종결 정의\|종결 조건'
0
```
**감사 주장 전건 참.** 행6(`어긋나지 않` → `2`)도 적중 둘 중 하나가 그 행 자신이었다.

### 왜 값만 고치면 안 되는가 (리드 지시 ①)

`3` → `6` 은 **다음 편집에 또 어긋난다**. 실제로 이 라운드가 그것을 증명했다(§4 참조). 그리고 이 표 바로 위 [HARD] 규칙이 「원시 개수로 못박지 않는다」를 선언하는데, **명제 축 두 행이 그 규칙을 스스로 위반한 형태**였다 — 값 축(행2~5)은 이미 `grep '^- 측정'` 으로 좁혀 같은 문제를 풀어 놓았는데, 새로 더한 명제 축에만 적용하지 않았다.

### 적용한 처방 — 제외를 명령 안에

값 축의 처방(범위를 좁혀 자기를 못 세게 함)을 명제 축에 맞게 구현했다. **명제는 산문에 살기 때문에 `^- 측정` 범위를 쓸 수 없다.** 대신 **표의 자기 적중 줄에 `[SWEEP-ROW]` 표지를 달고 명령에서 `grep -v` 로 뺐다** — 제외가 산문이 아니라 **명령 안에** 있고, 표지가 파일에 남아 감사 가능하다. 이는 이 SPEC 이 이미 검증한 패턴(`AC-016-EXEMPT`)과 같은 형태다.

**실행 확인:**
```
$ grep -n "어긋나지 않" spec.md plan.md acceptance.md | grep -vc 'SWEEP-ROW'
1
$ grep -n "종결 정의\|종결 조건" spec.md | grep -vc 'SWEEP-ROW'
3
```
표에 적힌 값과 일치한다.

### 판정 열 열거를 실물로 (리드 지시 ①)

거짓이던 「3번 항목」을 지우고 실제 셋으로 고쳤다 — HISTORY **0.3.0** 행 · `### 1.2 이 카드의 종결 정의` 제목 · 「실 세션은 종결 조건이 아니다」 문장. **다만 줄 번호가 아니라 앵커 문구로 적었다** — 이유는 §4.

## 3. P-02 — 행1 이 적은 명령이 적은 값을 내지 않는다

### 감사 주장 재현

```
$ grep -rn '/13\]' . 2>/dev/null | wc -l
17                                        ← SPEC 은 0 이라 적었다
$ grep -rn '/13\]' .moai/specs/SPEC-E2E-001/ | wc -l
0
```
**감사 주장 참.** 값 `0` 은 SPEC 디렉터리로 좁혔을 때만 참이고, 적힌 명령(`.` = 나무 전체)은 `17` 을 낸다 — 감사·개정 보고서와 다른 카드의 검증 산출물이 그 문자열을 정당하게 담기 때문이다. 「파일 전체에도 0 — 완전 소멸」이라는 판정 문구는 **거짓**이었다.

### 처리 (리드 지시 ②)

- 명령을 `grep -rn '/13\]' .moai/specs/SPEC-E2E-001/` 로 좁혔다.
- **「파일 전체에도 0」 문구를 삭제**하고, 왜 나무 전체가 대상이 아닌지(보고서·타 카드 산출물이 정당하게 담는다)를 판정 열에 적었다.
- 원칙을 한 줄로 남겼다: **「인용한 명령이 인용한 값을 내야 한다」.**

## 4. 이 라운드가 스스로 밟은 함정 — 줄 번호가 자기를 falsify 했다

P-01 을 고치면서 판정 열에 실물 줄 번호 `:25`·`:44`·`:54` 를 적었다. 그런데 **같은 라운드가 HISTORY 에 0.3.1 행을 하나 추가하자 그 셋이 전부 +1 밀려 즉시 거짓이 되었다.**

```
# 앵커로 고치기 전, 실행 확인
$ grep -n "종결 정의\|종결 조건" spec.md | grep -v 'SWEEP-ROW'
26:| 0.3.0 | …          ← 25 가 아니라 26
45:### 1.2 …            ← 44 가 아니라 45
55:**«실 Claude …       ← 54 가 아니라 55
```

**HISTORY 를 더하는 것은 개정마다 일어나는 일**이므로, 줄 번호로 못박은 열거는 구조적으로 매 개정 falsify 된다. 판정 열을 **앵커 문구**로 바꾸고, 그 이유를 표 아래 [HARD] 문단에 적었다 — 「줄 번호가 필요하면 읽는 시점에 명령으로 다시 얻는다, 문서에 박아 두지 않는다」.

**기록해 두는 이유**: 이것은 P-01(표가 자기를 센다)과 **다른 뿌리**다. P-01 은 「검사가 자기를 검사한다」이고 이것은 「고정 좌표가 문서 편집으로 이동한다」이다. 둘을 같은 것으로 묶으면 다음에 또 밟는다.

## 5. P-04 · P-05 — 권고 수용 (리드 지시 ④)

### P-04 — 「편집 불변」 주장의 범위를 나눴다

v0.3.0 은 「이 문장을 고쳐도 값이 흔들리지 않는다」고 적었는데 **넓었다**. 정확히는:

- **자기 명령문에는 불변** — 「표지의 출현」이 아니라 「금지어에 걸리는 줄 중 면제된 것」을 세므로, 필터·`grep` 인자에 표지를 아무리 써도 값이 안 움직인다.
- **자기 산문 인용에는 불변이 아니다** — 실측 7건이 전부 SPEC 자신의 인용이고 그중 셋이 이 기준 본문이다. 그 문장의 금지어 표현을 바꾸면 값이 정당하게 내려간다.

그래서 **판정을 등가에서 상한으로 완화**했다 — `7` **이하**이며 **초과 시 조사**. 등가였다면 정당한 편집이 허위 경보를 냈다(감사 지적대로 방향은 안전했으나 불필요한 빨강이었다).

### P-05 — 제외를 괄호에서 명령 안으로

```
$ grep -rn "E2E_FORCE_PORT\|boot-timeout" README.md package.json server channel | wc -l
0
```
v0.3.0 은 대상을 `.` 로 적고 「이 SPEC 문서 제외」를 **산문으로** 덧붙였는데, 적힌 그대로 돌리면 `25` 가 나왔다. **대상을 `README.md package.json server channel` 로 적어 제외를 명령 안에 넣었다** — P-02 와 같은 원칙이다.

## 6. P-06 — run 으로 이월 (리드 지시 ⑤ · 지금 고치지 않음)

AC-E2E-006 의 포트 점유 블록에 **공시된 잔여 위험**으로 적었다. 고치지 않은 이유를 함께 적었다:

- **`sleep 1` 은 경주다.** node 기동이 느리면 `$PORT` 가 비어 스크립트가 빈 포트를 스스로 잡고 정상 기동한다. **방향은 안전**(`exit 0 ≠ 9` → 빨강)이라 초록으로 새지 않는다. 다만 그때 빨간 이유가 「시한 폴링이 없어서」가 아니라 「Given 을 못 만들어서」이므로 진단이 흐려진다 → run M1 에서 **고정 대기 대신 준비 신호 대기**로 바꾼다.
- **`/tmp/t6-port.txt` 는 OS 가 비우는 자리다.** 저장소 규약은 검증 증거를 `.moai/state/verify/` 에 남기라 한다 → run M1 에서 경로를 옮긴다.
- **지금 고치지 않는 이유**: 둘 다 **실행해 봐야 형태가 정해지는데 이 나무에는 `node_modules` 가 없어 돌릴 수 없다.** 추정으로 고쳐 쓰면 재지 않은 값을 적는 것이 된다.
