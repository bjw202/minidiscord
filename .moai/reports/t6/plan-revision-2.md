## 2. N-01 — 기준선 변수 미바인딩 (`acceptance.md:163`·`:165`)

### 감사 주장 재현

```
$ unset BASE; git diff --name-only "$BASE"..HEAD; echo "exit=$?"
exit=0
```
빈 출력에 `exit=0`. 빈 리비전은 `HEAD..HEAD` 로 해석되므로 AC-E2E-013 의 측정 ①·③이 **무엇을 고쳤든 초록**이었다. **감사 주장은 참이다.**

### 부류로 훑음 (리드 지시)

한 자리만 고치지 않고 `$BASE` 를 쓰는 **실행 명령 전체**를 먼저 세었다:

```
$ grep -n '\$BASE' spec.md plan.md acceptance.md
acceptance.md:7    (규약 산문)
acceptance.md:134  ← AC-E2E-011 측정①   실행 명령
acceptance.md:136  ← AC-E2E-011 측정③   실행 명령 (생존 가드)
acceptance.md:163  ← AC-E2E-013 측정①   실행 명령
acceptance.md:165  ← AC-E2E-013 측정③   실행 명령
```

**실행 명령 4자리.** 감사가 지적한 것은 그중 둘이지만, 나머지 둘도 같은 미바인딩 위험을 안고 있었다(생존 가드조차 `"$BASE"` 로 적혀 있어, 변수가 비면 `git rev-parse --verify ""` 가 실패해 우연히 잡히긴 하나 그것은 설계가 아니라 요행이다).

### 고친 방식 — 위험의 원인을 제거

감사가 「더 싸고 확실하다」고 한 쪽을 택해 **네 자리 전부를 리터럴 `2a19d7d` 로 바꿨다.** 변수가 없으면 미바인딩도 없다. 여기에 더해 **비대칭 자체를 없앴다** — 기준선에 기대는 **두 기준 모두**가 생존 가드를 갖는다:

- AC-E2E-011 측정 ③ — `git rev-parse --verify 2a19d7d >/dev/null; echo "exit=$?"` → `exit=0` (기존, 리터럴화)
- **AC-E2E-013 측정 ④ — 같은 가드 신설.** v0.2.0 에 없던 자리다.

리터럴이어도 커밋 자체가 사라질 수는 있으므로(히스토리 재작성·얕은 클론) 가드는 여전히 필요하다. 그 이유를 규약 문단에 적었다.

### 재발 방지 — 자기 검사를 DoD 로

```
$ grep '^- 측정' acceptance.md | grep -c 'BASE'
0
$ grep -c '^- 측정' acceptance.md
34
```

DoD 7항이 이 값을 못박는다: **실행되는 측정 줄 34개 중 `BASE` 를 쓰는 것 0건.**

**파일 전체 개수로 못박지 않은 이유**를 함께 적었다 — 규약 문단·훑기 표·DoD 항목 자신이 `$BASE` 라는 글자를 담고 있어 원시 개수는 산문을 고칠 때마다 흔들리고, 못박으면 그것이 다시 N-02(기준이 자기를 센다)가 된다. 현재 원시 적중 5건은 전부 산문이다:

## 3. N-02 — 못박은 값 어긋남 + 측정이 자기를 셈 (`acceptance.md:205`)

### 감사 주장 재현

```
$ grep -c 'AC-016-EXEMPT' .moai/specs/SPEC-E2E-001/acceptance.md
4          ← SPEC 은 2 라고 적었다
```
**감사 주장은 참이다.** 합은 6 이 아니라 8 이었고, 기준은 **인도 시점에 이미 빨갰다**. 원인도 감사 진단대로다 — `acceptance.md` 의 네 적중 중 둘(측정 ①의 필터 인자, 측정 ①-b 자신의 `grep` 인자)이 **측정이 자기 정의 문장을 센 것**이다.

개정 1차 보고서(`plan-revision-1.md`)가 인용한 `acceptance.md:2` 는 **측정 ①-b 를 쓰기 전에 잰 값**이고, 그 문장을 추가하면서 다시 재지 않았다. 감사가 「실행하지 않은 명령을 인용했다」 부류로 분류한 것은 정확하다.

### 고친 방식 — 값이 아니라 **세는 대상**을 바꿨다

값을 8 로 고치기만 하면 다음 편집에서 또 어긋난다. 그래서 **표지의 출현**을 세는 대신 **금지어 패턴에 걸리는 줄 중 면제된 것**을 세도록 바꿨다:

```
$ grep -rE "수동 검증(을)? ?(수행|완료)|실 세션으로 (확인|검증)|사람이 (직접 )?확인했" \
    README.md .moai/specs/SPEC-E2E-001/ | grep -c 'AC-016-EXEMPT'
7
```

명령문 줄은 표지를 담고 있어도 **금지어 주장이 없으므로 세지 않는다.** 파일별 실측:

```
$ grep -E "<패턴>" .moai/specs/SPEC-E2E-001/spec.md       | grep -c 'AC-016-EXEMPT'   → 3
$ grep -E "<패턴>" .moai/specs/SPEC-E2E-001/acceptance.md | grep -c 'AC-016-EXEMPT'   → 3
   (plan.md 은 1 — 합 7)
```

### 편집 불변성을 실행으로 확인했다

못박는 문장 자체를 고친 **뒤** 같은 명령을 다시 돌렸다:

```
$ (못박은 숫자를 6 → 7 로 수정)
$ grep -rE "<패턴>" README.md .moai/specs/SPEC-E2E-001/ | grep -c 'AC-016-EXEMPT'
7          ← 흔들리지 않는다
```

v0.2.0 형태였다면 이 문장을 고치는 것만으로 값이 바뀌었다. **부류가 닫혔다.**

### 값이 6 이 아니라 7 인 이유 (실측)

N-03 을 닫으며 추가한 해설 줄이 금지어를 **인용**하면서 면제 표지를 함께 달았기 때문이다. 즉 정당한 인용이 하나 늘었다. **추정이 아니라 목록으로 확인했다** — 일곱 줄을 전부 출력해 각각이 「금지어를 정의·인용하는 문장」임을 읽었다.

## 4. N-03 — 면제 표지의 우회 통로 (`acceptance.md:199-207`)

### 감사 주장 재현

```
$ grep -rc 'AC-016-EXEMPT' README.md
README.md:0
```

사전 상태 0 이고, **그 0 을 못박는 측정이 없었다.** 측정 ①은 `README.md`·`scripts/` 에도 면제 필터를 걸고, 측정 ①-b 는 SPEC 3파일만 셌다 — 그래서 「실 세션으로 확인했습니다 `[AC-016-EXEMPT]`」 한 줄을 README 에 넣으면 **양쪽 모두 통과**했다. **감사 주장은 참이다.**

### 고친 방식

측정 ①-c 를 신설했다:

```
grep -rc 'AC-016-EXEMPT' README.md scripts/ 2>/dev/null   → 합 0
```
실측 사전 상태 `README.md:0`, `scripts/` 는 아직 없음.

두 측정의 대상 집합이 이제 맞물린다 — ①은 세 표면 모두에서 주장을 찾고, ①-b 는 SPEC 안의 정당한 면제를 세고, **①-c 는 SPEC 밖(주장이 실제로 오독을 낳는 표면)에 면제가 0 임을 잰다.** 산문으로만 있던 규약을 측정으로 내렸다.

## 5. N-04 — 종결 정의 명제 모순 (`spec.md:45` vs `:124`)

### 감사 주장 재현

`spec.md:45`(v0.1.0 에서 살아남음)는 「README 가 실제 배치와 어긋나지 **않는** 상태에서 닫힌다」였고, `spec.md:124`(v0.2.0 신규)는 「t26 이 닫을 때까지 README 안에 과도기적 어긋남이 **남는다**」였다. **동시에 참일 수 없다.** D5 반전이 :45 를 거짓으로 만들었는데 그 자리를 고치지 않았다. **감사 주장은 참이다.**

### 고친 방식 — 리드가 지정한 문언

리드 결정으로 **t26 소유가 확정**되었으므로 `:124` 가 참이고 `:45` 를 고쳤다. 리드가 지정한 형태 **«트리거는 t6, 「내 PC」 문구는 t26 이월 · 과도기 공시»** 를 그대로 §1.2 3번 항목에 넣었다:

> 3. **README 문구 갱신 — 트리거는 t6, 「내 PC」 문구는 t26 이월 · 과도기 공시.** 배포 경고 세 자리의 문언 교체와 보류 카드 트리거 세 줄 추가는 **이 카드(`t6`)가 한다**. 「내 PC에서만 도는 서버」 … 정정은 **카드 `t26` 으로 이월된다** … **그 과도기적 어긋남은 이 카드의 미결이 아니라 공시된 이월이며, `t26` 이 닫는다.**

이제 §1.2 · §3 D5 · §5 · AC-E2E-013 · `plan.md` M5 가 한 방향이다.

### 재발 방지 — **명제 훑기**를 값 훑기와 나란히 세웠다

감사 진단대로, 개정 1차의 훑기는 옛 **값**(`13`·`:173`·`sha256sum`·`124`)만 어간으로 열거해 **명제**를 놓쳤다. `spec.md` §7.3 에 두 축을 나란히 세우고, DoD 6항에 [HARD] 로 「결정을 뒤집을 때마다 그 결정을 전제로 쓴 문장을 어간으로 훑는다」를 넣었다.

## 6. 이 라운드가 스스로 밟은 함정 (숨기지 않고 적는다)

§7.3 훑기 표를 처음 쓸 때 **파일 전체의 원시 개수**를 적었다. 그런데 그 표와 DoD 항목이 그 값들(`:173`·`sha256sum`·`124`)을 문자로 담고 있어 **표가 자기를 셌다**:

```
$ grep -rn ':173' .   →  4   (v0.2.0 의 2 에서 늘었고, 늘어난 둘이 표와 DoD 자신)
$ grep -rn '124'  .   →  5
$ grep -n '\$BASE' …  →  4   (내가 방금 못박은 「정확히 2건」이 그 순간 이미 거짓)
```

**N-02 와 똑같은 뿌리다.** 발견 즉시 같은 방식으로 닫았다 — 원시 개수를 버리고 **규범 줄(실행되는 측정 줄 34개)** 로 범위를 좁혔다. 그 값은 산문을 아무리 고쳐도 흔들리지 않는다(실행 확인: `측정줄중BASE=0`, `측정줄중sha256sum=0`, `측정줄중124=0`).

기록해 두는 이유: 이 함정은 **한 번 고쳤다고 사라지지 않고 새 표를 만들 때마다 다시 생긴다.** 「훑기 표는 자기를 센다」를 부류로 알고 있어야 다음 표에서 걸리지 않는다.

## 9. 미검증 (Gaps) — 이 정리 라운드가 재지 않은 것

- **여전히 아무것도 실행하지 못했다 — E2E 도, 서버도, vitest 도.** `ls node_modules` → 없음. 세 라운드 모두 **정적 판독**이다. 새로 쓴 AC-E2E-006 의 점유자 확보 블록(N-05 수정)도 **돌려보지 않았다** — `node -e` 로 포트를 잡는 그 형태가 이 환경에서 실제로 동작하는지 확인하지 않았고, run 단계가 처음 잰다.
- **N-02 의 새 측정을 「우회 시도」로 시험하지 않았다.** 금지어 주장 한 줄에 면제 표지를 붙여 값이 8 로 오르는지 실제로 넣어 보지 않았다 — 논리로는 오르지만 관측하지 않았다.
- **N-03 의 측정 ①-c 를 「우회 시도」로 시험하지 않았다.** README 에 표지를 넣어 빨개지는지 확인하지 않았다.
- **`scripts/` 디렉터리가 아직 없어** 측정 ①-c 와 측정 ②의 `scripts/` 부분은 **빈 대상에 대해서만** 검증됐다. `2>/dev/null` 로 부재를 흡수하도록 썼으나, 디렉터리가 생긴 뒤의 거동은 run 단계가 처음 잰다.
- **`openDb(':memory:')` 변이**(1회차 D-15 이래 미검증)는 여전히 돌리지 않았다.
- **`tsx` 의 교차 워크스페이스 해소**, **음성 대조군의 실제 close 거동**도 여전히 미검증이다.
- **README 갱신 후 상태는 재지 않았다** — 모든 「갱신 후 기대」는 예측이다.
- **정본은 §2 t6 행과 §5 만 읽었다** — 다른 절에 t6 범위를 건드리는 문장이 더 있을 가능성은 배제하지 못한다(개정 1차와 같은 Gap).
- **2회차에 CLOSED 로 판정된 16건을 재검증하지 않았다** — 이번 정리가 그 자리를 깨뜨렸을 가능성은 §8 의 훑기가 닿는 범위 밖에서는 배제하지 못한다.
