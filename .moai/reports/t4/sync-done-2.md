### 8.1 정정 범위가 리드 지시보다 한 자리 넓다

리드 지시는 `:115-116` 두 줄과 인용 줄 번호 갱신, `:118`·`:201-202` 확인이었다. 확인 결과 **`:118` 과 `:202` 는 존재하지 않는 코드를 인용하고 있었다** — 두 곳 모두 방 대조 가드 `if (info.roomId !== roomId) return false` 를 `permissions.ts:49` 로 인용하는데, 이 코드는 파일 어디에도 없다(`grep -n 'roomId !== roomId' server/src/permissions.ts` → 무일치). 방 분리는 명시적 비교가 아니라 합성키가 방 번호를 품는 **구조적** 방식으로 바뀌었다. 따라서 두 곳은 «확인» 이 아니라 «정정» 대상으로 처리했다.

### 8.2 상태 전이 시작 상태가 지시와 다르다

리드 지시는 `implemented → completed` 였으나, 4개 SPEC frontmatter 의 실제 관측값은 전부 `status: in-progress` 였다(`sed -n '1,12p'` 로 각각 판독). 3단계 종결(`in-progress → implemented → completed`)의 종착점이 `completed` 로 같으므로 지시한 종착 상태를 그대로 적용하고, 출발 상태만 관측값으로 기록한다.
