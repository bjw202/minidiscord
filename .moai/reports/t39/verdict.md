## 2. §5.5 대조 판정 — `미관측` (PASS 아님, 카드는 열린 채)

- 병렬 팔 실패 Mp = **0**, 직렬 팔 실패 Ms = **0** → §5.5 사상 결과는 **`미관측`**이다. `PASS` 로 적는 것을 이 SPEC 은 금지한다(REQ-WSUPGRADE-008, AC-009).
- **(ㄴ) 이 판정의 뜻 — «현상이 없다»가 아니라 «조건이 재현되지 않았다»다.** 카드가 열린 채인 것은 정확히 그 이유 때문이다.
- **(ㄱ) 이번 회차가 원 조건을 재현하지 못한 이유(리드 재판독 2026-09-05, 기록에 편입).** 이번 두 팔은 **서버 스위트 안의 파일 병렬성만** 갈린다(SPEC §B 정의 그대로 실행했다 — 실행이 계획을 벗어나지 않았다). 그러나 원 관측은 `moai gate`, 그 뿌리 `npm test --workspaces --if-present` 가 **server 와 channel 을 함께** 도는 창에서 나왔다. channel/test 에는 서버·포트를 띄우는 파일이 다섯 있다(permission-relay · index-wiring · transport-auth · gateway-mutual-auth · gateway-client — 전부 gateway/WebSocket 계열). 갈래 H-1·H-2 는 «같은 127.0.0.1 포트를 쥔 다른 앱»을 요구하는데, 이번 두 팔에는 그 외부 앱이 **없었다** — 경합 상대는 서버의 자기 시험들뿐이었다. 즉 **M3 는 원 조건을 아예 갖고 돌지 않았고, 이것은 run 의 이탈이 아니라 SPEC §B 설계의 갭이다.**
- **(ㄷ) 다음 회차 조건 — 제안으로만 기록한다(실행하지 않았다).** 팔 정의의 소유는 SPEC §B 이고 SPEC 본문 수정은 manager-spec 의 몫이다. 제안: 대조 축을 «서버 안 파일 병렬성»에서 **«워크스페이스 동시 실행»**으로 바꾼다 — 병렬 팔 = `moai gate`(또는 `npm test --workspaces`), 직렬 팔 = 워크스페이스 순차 실행, 그 밖의 인자·환경 동일. **D-1 과의 구분을 명시한다**: D-1 은 **인공 배경 부하 스폰**을 금지한다. 이 제안은 관측된 실패가 나온 **실제 명령을 그대로 도는 것**으로, 빠진 기존 조건을 채우는 것이지 부하를 발명하는 것이 아니다 — 축이 다르다.
- acceptance 미관측 처분이 나열한 원 옵션들(회수 상향 · 다른 기계 · CI 위 실행)은 위 제안과 함께 리드의 처분 자료로 남긴다. 이 기록은 어느 쪽도 권하지 않는다.

포획된 응답 바이트가 존재하지 않으므로, §5.4 지문표와 2차 판정은 **합성 입력에서만** 실행됐다(M2 시험 8건 + M4 변이). «누가 답했는가»에 대한 실측은 이번 회차에 하나도 없다 — 지문표는 다음 회차에 실제 바이트를 만나기 전까지 검증되지 않은 기계로 남는다.

## 5. 수리 설계 없음 — 후속 카드의 씨앗

**이번에 알게 된 것.**

1. 선언된 두 팔(파일 병렬 스위치 축)에서는 40회 전부 초록이었다 — 이 축에는 경합 상대가 없었다(§2 (ㄱ)).
2. **관측 하네스가 던짐 경로를 삼킨다(실행으로 확정).** `ws` 는 `unexpected-response` 리스너가 존재하면 `abortHandshake` 를 건너뛴다(`websocket.js:929` — emit 은 리스너 반환과 무관하게 참). 그래서 트리거 실패의 모습이 «즉시 오류»에서 «5초 시간 초과»로 바뀌었고, plan.md §C 가 상정한 «리스너가 값을 돌려주지 않으면 emit 이 거짓»은 성립하지 않는다. 후속 카드는 **기록 뒤에 실패를 스스로 다시 세우는 리스너**(예: 소켓 파기·약속 거절)가 필요하다 — AC-005 기준 실패의 수리도 같은 자리에서 온다.
3. 포트 보유 상태·귀속·창 경계의 **기록 형태와 판정기는 실측됐다** — 트리거 400 으로 얻은 기록이 14항목 전부를 통과했다(`ac001-baseline-capture.json`). 다음 회차의 404 포획은 같은 기계로 바로 판정된다.
4. H-2 의 기제 재현(probe-coexist)은 여전히 이 카드의 유일한 도달성 근거다.

**다음에 무엇을 재야 하는가.** (가) §2 (ㄷ) 의 워크스페이스 동시 실행 축에서 20+20(팔 정의는 manager-spec 이 SPEC 본문에 새긴 뒤), (나) 그 창에서의 포획 1건 — 지문표·2차 판정·도달성 검증이 이미 서 있으므로 포획 즉시 판정 가능, (다) H-1·H-3 의 입력 조합을 내는 탐침(도달성 근거 채움).
