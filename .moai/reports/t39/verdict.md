## 4. AC-005 — 재설계된 기준의 이빨 (반대 방향 변이 둘, 실측 전문)

1회차가 샌 자리는 «삼킴»이었다 — 리스너가 던짐을 삼켜도 시험은 여전히 failed 지만 실패의 모양이
«5초 시간 초과»로 바뀌고, «실패했는가»만 재던 앞 기준은 그것을 잡지 못했다(CRITERION-FAILURE).
v0.7.0 이 세운 기준은 **포획 존재(1) + 실패(2) + 실패가 관측 코드를 실은 응답자 오류(3)** 셋을 함께
요구하고, 판정기 `m4r2/ac005-verdict.mjs` 로 기계로 잰다.

**기준선(수리된 하네스 + 트리거)** — 세 조항 전부 PASS:

```
AC-005 판정 — .moai/reports/t39/m4r2/ac001-trigger-baseline.log
  실패 메시지: Error: Unexpected server response: 400
(1) 포획 기록 존재(1건 이상): PASS
(2) 대상 시험 failed: PASS
(3) 실패가 관측된 상태 코드를 실은 응답자 오류(시간 초과 아님): PASS
AC-005: PASS — 세 조항 모두 성립
```

**본 변이(삼킴 — 재수립 두 줄만 삭제, 기록은 산다)** — 조항 (3)에서 RED:

```
  실패 메시지: Error: Test timed out in 5000ms.
(1) 포획 기록 존재(1건 이상): PASS
(2) 대상 시험 failed: PASS
(3) 실패가 … 응답자 오류(시간 초과 아님): FAIL
AC-005: RED — 어긋난 조항: (3)
```

**보조 변이(은폐 — 리스너 통째로 삭제)** — 조항 (1)에서 RED:

```
  실패 메시지: Error: Unexpected server response: 400
(1) 포획 기록 존재(1건 이상): FAIL
(2) 대상 시험 failed: PASS
(3) … n/a(포획 부재 — 비교할 코드 없음)
AC-005: RED — 어긋난 조항: (1)
```

**두 변이는 서로 반대 방향이고 서로 다른 조항에서 어긋났다** — «기록을 지키려다 실패를 삼키는» 쪽은
(3)에, «실패를 지키려다 기록을 잃는» 쪽은 (1)에 걸렸다. 1회차를 죽인 바로 그 변이(삼킴)가 이제
잡힌다. 전문: `m4r2/ac005-{baseline,primary,aux}-verdict.txt`·`mutations-round3.md` §표.

## 5. AC-013 — 공허 통과의 기록 (리드 지시문 반영)

**AC-013 은 이번 실행에서 공허하게(hollow) 통과했다.** 두 조항을 따로 적는다:

- **조항 (1) — 시행 수 20: 통과.** `m6/summary.txt` 의 trial 행은 정확히 20행이고 중도 종료 흔적이 없다.
- **조항 (2) — 첫 포획 이후에도 시행이 이어졌는가: 전제 불성실(premise-unmet).** 포획이 0건이라
  «첫 포획 이후 지속»을 잴 사건이 한 건도 없다 — **AC-013 의 중심 물음은 이번 실행으로 행해지지
  않았다.** 20행 전부 초록인 복제 기록만으로는 «고정 20회»의 절반(회수)만 확인한 것이다.

판정기(`m4r2/ac013-check.mjs`)의 실측 출력:

```

  정지 규칙(조항 (2)): 전제 불성실 — 포획 0건이라 «첫 포획 이후 지속»을 잴 사건이 없다
AC-013: PASS(조항 (1)만) — 정지 규칙 조항은 전제 불성실(공허 통과 주의)
```

**AC-013 의 이빨은 이번 실행의 어디에도 없고, 오직 `m4r2/` 의 두 변이에만 있다** — 본 변이(다섯째

## 6. `미관측` 은 실패가 아니다 — 그리고 이 카드는 여기서 닫는다

- 세 기록(복제 0/20 · 병렬 0/20 · 직렬 0/20)의 판정은 전부 **`미관측`** 이며 `PASS` 가 아니다
  (REQ-008·AC-009 — 침묵은 통과가 아니다). «현상 없음»이 아니라 **«조건이 재현되지 않았다»**다.
- **§D-2 종결 규약(운영자 확정)** — 이 카드는 3회차 뒤 결과와 무관하게 닫는다. **«이 비용대에서는
  여기까지»** — 복제 20회가 주는 `p ≤ 13.9%`(나무 환경 한정)는 값이고, 161회는 이 카드의 값에 맞지
  않는다(plan.md §D-2). 남는 표집은 **`REQ-WSUPGRADE-013` 의 상시 관측자**가 비용 0으로 이어받는다
  — 수리된 하네스(`b7f22d0`)가 스위트에 남아 이후 모든 gate·CI 실행이 자동 시행이 된다(평상시 비용
  0 은 AC-014 가 기계로 잰다).
- **수리 설계는 없다.** 후속 카드의 씨앗은 «무엇이 밝혀졌고 다음에 무엇을 재야 하는가»까지다 —
  H-1·H-3 의 도달성 근거 채움은 실제 포획 또는 그 조합을 내는 탐침의 출력으로만 가능하고, 그 표집
  주체는 이제 상시 관측자다.

## 7. 실행 환경 기록 (1회차 §6 에서 이어짐 — 변화 없음)

이 카드의 모든 실행은 «나무의 소스 + 주 체크아웃의 패키지» 혼합 환경에서 돈다(server/node_modules 는
캐시만 있고 패키지는 주 체크아웃에서 해석된다). «효과 동일»은 추론이지 측정한 동치가 아니다. 3회차의
M6·M3 재실행도 같은 조합에서 돌았고, 환경은 고치지 않았다(고치면 1~3회차 측정의 조건이 사라진다).
