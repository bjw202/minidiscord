## 5. Gaps (미검증)

- **변이표의 행별 예측은 13행 중 6행만 실측과 일치했다.** 7행(C·F·G·H·I·J·M)은 결합 차이 — 무너뜨린 기준이 표보다 많거나(H·I·J·M·G), 표가 예측한 기준이 생존했다(C-009: 양쪽을 함께 바꾸면 009 가 «전체 규칙 불일치»라는 잘못된 이유로 통과 · I-011: proof 가 아예 없는 위조는 존재 검사에도 거절). **어느 변이도 스위트 전체로는 놓치지 않았으므로 방어 구멍은 없지만**, «무엇이 무엇을 잡는가»의 귀속 지도로서 표는 부분적으로 틀렸다. 표는 plan-done §5 가 인정한 대로 연역이었다. **교정은 acceptance.md 본문 소유(manager-spec)라 run 이 하지 않았다** — 실측값 전체가 progress.md §E.2.4 에 있으므로 sync 가 그것으로 표를 고친다.
- **변이 N 이 AC-CHANINJECT-007 도 무너뜨렸다** (표는 AC-CHANAUTH-001·003·004·005 «만» 이라고 적었다). 같은 게이트를 공유하는 형제 기준이 하나 더 있다는 뜻이고, N 의 핵심 기대(AC-GWAUTH 0건)는 그대로 성립한다.
- **plan §F M3-5 후반부를 수행하지 않았다** — `routes-bots.ts:9-10` 주석에 «그리고 채널 사본» 추가. plan §A PRESERVE 목록과 AC-GWAUTH-014 집합이 같은 파일을 배제하므로 **기계적으로 검증되는 쪽을 따랐고**, 채널 쪽 @MX:ANCHOR(정본 `routes-bots.ts:11` → 사용 지점 `gateway.ts`)는 착지했다. 이 이월이 옳은 판정인지는 sync 감사의 몫이다.
- **AC-GWAUTH-009 의 첫 변이 절(HMAC 메시지를 nonce 하나로)은 009 를 무너뜨리지 않는다** — 양쪽을 함께 바꾸면 모든 프레임이 거절되어 009 가 공허하게 통과한다. 둘째 절(채널이 상수로 재계산)은 무너뜨린다. 기준 본문은 두 절을 다 적고 있어 기준 자체는 성립한다.
- **SPEC-GWAUTH-001 자기 문서의 줄 인용이 M4/M5 코드 편집으로 밀렸다.** §B-0 훑기로 실측한 새 앵커 목록은 §E.2.9 ③ — 자기 SPEC 본문은 manager-spec 소유라 run 이 고치지 않고 목록만 넘긴다. (`spec.md:246` 의 `:136`·`:89` 인용은 R-06 이전부터 낡았다 — 실제 `:149`·`:162`.)
