## 1. 주장 (Claim)

**계약 개정 여덟 자리는 내용이 옳다.** 가장 넘치기 쉬운 자리 — `CHANCLIENT` §5 의 «상대 인증은 여전히 없다» → «생겼다» 뒤집기 — 가 과장하지 않았다. 그 문단은 뒤집은 직후 «**그래도 남는 것을 정확히 적는다**» 로 두 잔여(토큰·`token_hash` 보유자 / 내용 신뢰 경계)를 명시하고, C-03 이 세운 경계와 **글자 단위로 일치한다**(`token_hash` 를 이름으로 부른다). §4.2 머리 주석도 «토큰(**또는 그 저장 해시**) 지식의 증거» 로 적었다. 서버 쪽 «형제 기준 0건 파손» 주장도 네 파일을 직접 열어 **확인했다 — 옳다.**

**N-03·N-04 는 모범적으로 닫혔다.** 변이 O 의 형태가 세 자리에 [HARD] 로 못 박혔고, 하네스 접근자 넷이 «AC 가 실제로 쓰는 것 전부» 라는 표제와 함께 선언됐으며, 내가 든 «AC-015 는 다른 하네스라 `nonceSeen()` 이 없다» 까지 그 자리에 적혔다.

**그러나 이번 라운드는 자기 문서를 세 곳에서 모순 상태로 만들었다.**

- **§3.2 는 아직 개정 이전 세계를 서술한다.** 절 제목이 «개정 필요 — **이 SPEC 이 수행하지 않았다**» 이고, 본문이 «**이 카드는 그 개정을 아직 수행하지 않았다** … run 진입 전에 닫혀야 할 항목» 이라고 적는다. 같은 절 아래쪽(:201)과 §5(:415-417)와 `plan.md` §B 는 «수행했다 · 해소됐다» 고 적는다. **한 절이 자기 자신과 어긋난다.**
- **F-A8 자리 수가 문서마다 다르다** — `spec.md` §5 는 **10**, `CHANINJECT/spec.md:27` 은 **11**, `spec.md` §3.3 은 **12**.
- **`plan.md` §B 와 HISTORY 의 형제 인용 일곱 자리가 전부 개정 이전 위치를 가리킨다.** 같은 여덟 자리를 `spec.md` §3.3 에서는 **전부 정확하게** 다시 뽑았으므로, 훑기는 **한 파일에서만 수행됐다.**

그리고 **`M1 단계 0`** 이 다섯 자리에 살아 있는데 M1 은 «완료됨» 으로 바뀌었다 — `spec_base_sha` 를 기록할 단계가 사라졌고, `acceptance.md:76` 이 «기준 SHA 가 없으면 범위 경계 기준은 통과가 아니라 **실패**» 라고 적으므로 **AC-GWAUTH-014 가 자기 규칙으로 실패한다.**

내가 직접 훑은 미독 형제 셋에서 **개정 집합이 놓친 자리 넷**을 찾았고, 그중 둘은 M4 가 고칠 하네스의 **명세 원본**이다. 그리고 작성자 자신의 B/C 판별 기준을 표 전체에 다시 적용한 결과 **한 행이 기준을 통과하지 못한다** — REQ-CHANAUTH-002.

### 2.2 후속 소유자를 지목하지 않은 판단 — **원칙적이다, 회피가 아니다**

**원칙적이라고 판단하는 근거 셋.**

1. **전제가 미검증이다.** F-A8 은 감사도 이 SPEC 도 **도달성을 실측하지 않은 추정**이다. 확인되지 않은 결함에 소유 SPEC 을 붙이는 것은 「결함 주장은 도메인 도구가 확인하기 전까지 가설이다」라는 이 프로젝트의 명시적 규범(`verification-claim-integrity.md` §1.1 surface 3)을 정면으로 어긴다. **이 카드가 고치러 온 부류와 같다** — 작성자의 논거가 정확하다.
2. **대가를 감추지 않았다.** `spec.md:411` 이 내가 든 지적을 그대로 받아 적는다 — «**소유를 카드에 남기면 F-A8 만은 그 문제로 되돌아간다** … 인계 항목 넷 중 셋은 SPEC·REQ 번호로 이어졌는데, F-A8 의 포인터는 이 SPEC 이 착지하면 **곧 닫힐 카드**를 가리킨 채 남는다». 그리고 «**그 상태를 만든 것은 이 SPEC 이다**» 라고 귀속까지 적었다.

**회피였다면** 소유자도 없고 기록도 없고 재개 조건도 없었을 것이다. 셋 다 있다. **원칙적이다.**

## 3. Part B — 형제 계약 개정 여덟 자리

### 3.1 내용의 정확성 — 넘치지 않았다 ✅

가장 위험한 자리부터 판정했다.

**`CHANCLIENT/spec.md:239` (§5, «상대 인증이 생겼다»)** — 뒤집기 자체는 옳다. 그리고 뒤집은 **직후** 이렇게 적는다.

> **그래도 남는 것을 정확히 적는다**: ① 토큰·`token_hash` 를 아는 상대, 손상된 서버는 여전히 통과한다(`SPEC-GWAUTH-001` §5) ② 밀어 넣어진 본문의 내용 신뢰 경계는 상대를 인증해도 해결되지 않는다 … 아래 v0.3.0 서술의 위협 기술은 **그 두 잔여의 범위에서만** 유효하다.

**C-03 의 경계와 정확히 일치한다** — `token_hash` 를 이름으로 부르고, 「토큰을 모르는 모든 상대」로 줄이지 않았다. 과장 없음.

**§4.2 머리 주석(`:142`)** — «이제 `welcome` 은 토큰(**또는 그 저장 해시**) 지식의 증거다» + 두 겹 전제 분리(순서 위생 / 상대 신원) + «**이 SPEC 이 배제하지 못하는 것도 함께 적는다**: 토큰 또는 `bot_tokens.token_hash` 를 아는 상대는 … 두 겹 모두를 통과한다». ✅

**나머지 여섯 자리** — REQ-001(«필드는 이 **셋**뿐이며» + 소유를 `SPEC-GWAUTH-001` REQ-001·002 로 귀속), REQ-003(«증명이 대조를 통과하면» + «통과 충실성은 한 글자도 바뀌지 않는다 — 바뀌는 것은 «언제 부르는가» 뿐»), 필드 열거, 흐름도, 용어표, `SPEC-GATEWAY-001` REQ-GW-001(원문 유지 + 조건부 절 추가, «위 조회·등록·`welcome`·재전송 순서와 … 나머지 판정은 **한 글자도 바뀌지 않는다**»). **전부 정확하고, 소유를 이 SPEC 으로 귀속하는 형태가 일관된다.** ✅

### 3.2 REQ-GW-001 의 «형제 기준 0건 파손» — **검증했다, 옳다** ✅

네 파일 전부 열어 `hello` 발신과 `welcome` 소비를 확인했다.

gateway.test.ts:79 / :178 / :824      web-permission-contract.test.ts:85 / :257

일곱 자리 전부 **논스 없는 `hello`** 이고, `permissions`·`room-members` 는 `type === 'welcome'` 분기만 한다. 1회차에 확인한 `gateway.test.ts:82`·`:143-145`(세 필드 배열)·`web-permission-contract.test.ts:261`(`toMatchObject`)와 합쳐, **필드가 하나 늘어도 깨지는 자리가 없다.** 주장이 맞다.

### 3.3 `proof?: string` — 하향 협상은 열리지 않았다. 다만 근거가 틀렸다

**하향 협상 경로는 닫혀 있다.** 채널은 REQ-GWAUTH-001 로 **항상** 논스를 싣고, REQ-GWAUTH-006·008 로 증명 없는 `welcome` 을 거절한다. AC-GWAUTH-006(증명 생략 → `notes` `[]` · `verdicts` `[]` · `settled === 'pending'`)과 변이 H·I 가 «증명이 없으면 통과시키는 하위 호환 갈래» 를 기계적으로 금지한다. **1회차에 정리한 판정이 유지된다.** ✅

**그러나 옵셔널의 근거가 이 콜백에 맞지 않는다.** `CHANCLIENT` HISTORY ④ 가 적은 이유:

> **옵셔널(`?`)로 둔 이유**는 논스 없는 `hello` 에 서버가 증명 없는 `welcome` 을 돌려주는 갈래가 계약에 살아 있기 때문이다(`SPEC-GWAUTH-001` REQ-GWAUTH-004)

그 갈래는 **논스를 보내지 않는 클라이언트**(서버 테스트 하네스)의 것이지, 이 SPEC 의 클라이언트의 것이 아니다. 이 클라이언트는 항상 논스를 보내고, 증명이 없으면 `onWelcome` 을 **부르지 않는다** — 같은 라운드에 개정한 REQ-CHANCLIENT-003 본문이 그렇게 적는다. 즉 **`onWelcome` 이 증명 없는 프레임을 받는 상태는 계약상 발생할 수 없다.**

옵셔널 자체는 타입으로 틀리지 않지만(상위 타입), **소비자 계약이 배제한 상태를 API 표면에 문서화하면서 그 이유로 다른 클라이언트의 갈래를 든다.** 코디네이터가 지목한 대로 하향 구현이 숨을 자리이며, AC 가 막고 있을 뿐 문서는 그것을 정당화한다.

**그리고 선언이 여전히 불완전하다.** 현재 `:93`:

```ts
onWelcome?: (w: { room_id: number; bot_id: number; bot_name: string; proof?: string }) => void
```

`missed_after_id` 와 `type` 이 없다. REQ-CHANCLIENT-003 은 «프레임 객체 그대로» 를 명령하고 AC-GWAUTH-015 는 `missed_after_id: 42` 와 `type: 'welcome'` 을 포함한 프레임으로 `toEqual` 을 잰다. **작성자 자신의 §3.3 행이 «`welcome` 이 `proof` 를 싣고(그리고 이미 `missed_after_id` 를 싣고)» 라고 적어 두고도 `proof?` 만 더했다.** → **R-07**

### 3.5 B/C 판별 기준 재적용 — 한 행이 통과하지 못한다

작성자가 세운 기준(`spec.md:247-254`): **C** = «SPEC 이 자기 설계 결정·자기 카드의 미이행을 기록 (날짜가 박힌 역사적 진실)», **B** = «시스템의 현재 동작·현재 상태를 서술 (독자가 «지금의 사실» 로 읽는다)». 모든 C 행에 다시 적용했다.

| C 행 | 재적용 결과 |
|---|---|
| `CHANAUTH` §2.1 제목 «`welcome` 은 인증의 증거가 아니다» | **C 유지 가능.** 현재 상태 서술의 형태지만, 그 절의 기능이 «t9 카드가 상호 인증을 세우지 **않았다**» 의 기록이다. 두 다리가 겹치는 자리이며 미이행 다리가 우세하다 |
| `CHANAUTH` §1 세 겹 표 ①칸 «인증 장치가 아니다» | **C 유지 가능.** 같은 논리 |
| `CHANCLIENT/progress.md:352` «상대 신원 층은 닫히지 않았다» | **C 유지 가능.** 제목이 «**이 판정이 닫지 않는 것**» 이고 `progress.md` 는 시점 기록 문서다. 내포된 현재 상태 절(«`welcome` 은 토큰 지식의 증거가 없어»)이 있어 순수하지는 않지만, 문장의 단언 골격이 미이행 기록이다. **작성자 분류가 옳다** |
| **`CHANAUTH` REQ-CHANAUTH-002** | **B 여야 한다 — 기준을 통과하지 못한다** |

**REQ-CHANAUTH-002 원문(`spec.md:198`)**:

> `welcome` 프레임이 도착하면 그 소켓은 세션 확립됨 상태가 되어야 하고, `onWelcome` 콜백은 종전대로 호출되어야 하며, 이후 도착하는 세 프레임은 종전과 같은 방식으로 분배되어야 한다.

이것은 결정의 기록도 미이행의 기록도 아니다. **시스템이 무엇을 해야 하는가를 명령하는 규범 조항**이고, 독자는 그것을 «지금의 계약» 으로 읽는다 — 작성자 자신의 B 정의 그대로다.

**결정적인 것은 이 패스 내부의 선례다.** `SPEC-GATEWAY-001` REQ-GW-001 은 (ⅰ) `status: completed` SPEC 의 (ⅱ) 규범 조항이고 (ⅲ) `welcome` 관련 열거가 거짓이 된다 — **REQ-CHANAUTH-002 와 성질이 같다.** 그런데 REQ-GW-001 은 **B 로 분류되어 개정됐고**(v0.4.0), REQ-CHANAUTH-002 는 C 로 남았다. `completed` 여부로는 두 자리를 가를 수 없다(둘 다 `completed` — 실행 확인).

그리고 REQ-GWAUTH-006 이 §4.3 에서 «이 조항이 `SPEC-CHANAUTH-001` REQ-CHANAUTH-002 의 «`welcome` 이 도착하면 확립된다» 를 **좁힌다**» 고 적는다. **살아 있는 SPEC 이 명시적으로 좁히는 규범 조항을 개정하지 않고 두는 것**은 카드 `t9` 를 계획 감사 C-03 으로 되돌린 상황과 같다.

작성자는 «**나머지 C 행은 기준을 적용해도 C 로 남는다**» 고 적었다. **한 행은 남지 않는다.** → **R-05**
