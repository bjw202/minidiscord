**그런데 왜 0.50 에 두지 않는가 — 세 가지가 위로 민다.**

**아래로 미는 것 하나 — 발견 ① 은 「미검증」이 아니라 «인도된 기능의 부족» 이다.**

**그래서 `0.68`.** 0.50 앵커 문언이 그대로 참인 상태에서, 위 세 가지 때문에 그 앵커보다 확실히 위이고, 0.75 는 그 문언이 두 겹으로 거짓이라 닿지 않는다. **리드가 0.72~0.75 로 판정한다면 그것이 부당하다고 말하지 않겠다** — 근거 ③(정직한 보고를 벌하지 않는다)을 더 무겁게 다는 판단이며, 그 자리는 리드의 것이다. **다만 그 판단이 §6 의 문턱을 정확히 가른다는 사실을 함께 적는다.**

## 3. 새 회귀를 공격했다 — 리드가 가장 공격받길 원한 자리

**기준선 못박음**

```
$ git rev-parse HEAD:server/test/live-extract-lib.ts
c8e32fae9974d258cbc9f4ce3e56c05887893ea5
$ npx vitest run test/live-extract.test.ts --root server

```

### 3.1 변이 A — B3 수리(e5 쪽)를 되돌린다 → **정확히 새 시험만 빨개진다**

`writeFileSync(..., maskTokens(\`unmeasured_path=e5…\`))` 의 `maskTokens(` 를 벗겼다(1줄).

```
     × e5 갈래가 전역 항목을 실을 때 토큰 전문이 남지 않는다 — B3 수리를 고정한다  5ms
      Tests  1 failed | 57 passed (58)     exit=1
```

**5회차에서 이 변이는 58건 전부 초록이었다. 이제 빨개진다.** 리드의 자기 신고가 이 트리에서 재현된다.

### 3.2 변이 A2 — manifest 쪽 수리를 되돌린다 → **초록. 그리고 그 사유가 참인지 내가 따로 검사했다**

```
      Tests  58 passed (58)     exit=0
```

카드는 그 자리에 「단위 시험이 그 산출에 64자 hex 를 밀어 넣을 입력 경로가 없다」고 적었다. **받아들이기 전에 확인했다** — `ManifestItem` 은 `name`·`judge`·`status`·`files`·`verdict?`·`note?` 여섯 열쇠이고(`:27-35`), `verdict`·`note` 에 들어가는 값을 전수로 읽으면 **전부 리터럴**이며(`:206`·`:207`·`:224`·`:250`·`:270`·`:288`·`:304`), `files` 는 고정 파일명, `name` 은 항 이름이다. **자유 문자열이 외부 입력에서 오는 경로가 없다. 사유가 참이다.**

### 3.3 변이 D — e5 갈래 자체를 막는다 → **둘이 빨개진다**

`if (entryBefore !== entryAfter)` 를 `if (false && …)` 로 바꿨다.

```
     × e5 갈래가 전역 항목을 실을 때 토큰 전문이 남지 않는다 — B3 수리를 고정한다
     × 실행 중 전역 항목의 내용이 바뀌면 귀속을 포기하고 e5 를 적는다
      Tests  2 failed | 56 passed (58)     exit=1
```

**새 시험은 「가림 함수의 출력 모양」이 아니라 «갈래에 실제로 들어갔다 + 그 산출에 전문이 없다» 둘을 함께 건다.** 형태가 다른 두 변이(수리 제거 / 갈래 차단)에 각각 다르게 반응하므로, 우연히 맞는 모양이 아니다.


**lib diff 에 변이 잔재 없음. 추적 파일 어느 것도 수정되지 않았다.**

### B1' [Medium-High · **차단**] 앞 회차가 요구한 「낡은 인용 정리」가 집행되지 않았다 — 일곱 자리가 코드의 엉뚱한 줄·구간·값을 가리킨다

## 6. 감도 분석 — 무엇이 0.80 으로 옮기는가

가중 조화평균(40/25/20/15). Security 상한은 `ps eww` 잔여로 0.85 대에 눌린다.

| 시나리오 | F | S | C | Co | 총점 | 0.80 |
|---|---|---|---|---|---|---|
| **현행 (6회차 실측)** | .68 | .82 | .90 | .72 | **0.756** | ✗ |
| B1'·B2' 를 닫는다 (Co → .90) | .68 | .82 | .90 | .90 | 0.780 | ✗ |
| **Functionality 만 리드가 .75 로** | **.75** | .82 | .90 | .72 | 0.788 | ✗ |

| Co 만 만점 · F 는 내 값 | .68 | .82 | .90 | 1.00 | 0.789 | ✗ |
| F 내 값 · 나머지 전부 만점(이론 상한) | .68 | 1.00 | 1.00 | 1.00 | 0.842 | ✓ |

**읽어야 할 것 셋.**

1. **리드가 물은 것에 정확히 답한다 — 「Functionality 판독만이 막고 있는가?」 아니다.** 제 값을 리드가 원했던 `0.75` 로 올려도 `0.788` 이다. 반대로 문서 결함을 전부 닫아도 제 값이 `0.68` 이면 `0.780` 이다. **둘이 함께 움직여야 넘는다.**
2. **문턱은 계산할 수 있다.** B1'·B2' 를 닫아 Co 를 `0.90` 으로 올린 뒤(S `.82`·C `.90` 고정) 통과에 필요한 Functionality 는 **`≥ 0.719`** 다. 즉 리드가 `0.72` 이상으로 판정하면 통과하고 그 아래면 미달이다 — **철회된 두 값(리드 `0.75`·4회차 `0.70`)이 그 문턱을 사이에 두고 갈라져 있다.** 이것이 리드 재정이 필요한 좁은 물음이다.
3. **닫을 것은 전부 범위 안이다.** B1'·B2' 는 이 카드가 소유한 `spec.md`·`progress.md`·`CHANGELOG.md` 의 편집이고 **구현 변경 0줄**이라 §5 의 설정 파일 「정확히 둘」 선언과도 `AC-016` 의 「더해진 줄 1」과도 부딪히지 않는다. **범위 밖이라 못 하는 것은 하나도 없다.**

8. **B1' 훑기의 «결과 개수» 를 이 보고서의 문장으로 세지 않았다** — §5 가 **명령**을 싣고, 그 정의역에 `.moai/reports/` 를 넣지 않았다.
