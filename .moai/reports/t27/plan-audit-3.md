## 5. 발견

### 차단 (blocking) — 4건

**R3-1 — AC-CI-011 은 자기가 이름 붙인 표를 통째로 지워도 초록이다**
`acceptance.md:460-495` — Severity: critical — Class: blocking

기준의 제목은 「**결정 파급표의 완전성**이 기계로 확인된다」이고 검증 대상은 「`plan.md` §D-2 결정 파급표」(`:491`)다. 그런데 명령이 읽는 것은 **선언(`OD-DEP-EXPECT`)과 마커(`[OD-DEP:N]`) 둘뿐이며, §D-2 표를 한 줄도 읽지 않는다.**

```
### epsilon - §D-2 파급표 본문을 통째로 삭제; 마커·선언 무변경
  declared {1: 5, 2: 5, 3: 7} / actual {1: 5, 2: 5, 3: 7} -> FALLOUT TABLE COMPLETE
  RESULT: PASSED  <-- 장치가 잡지 못함

### zeta - §D-2 의 「그 밖의 자리」 셀을 전부 비움
  declared {1: 5, 2: 5, 3: 7} / actual {1: 5, 2: 5, 3: 7} -> FALLOUT TABLE COMPLETE
  RESULT: PASSED  <-- 장치가 잡지 못함

### alpha - 비종속 자리에 마커 + 선언 상향 (표는 그대로)
  declared {1: 6, 2: 5, 3: 7} / actual {1: 6, 2: 5, 3: 7} -> FALLOUT TABLE COMPLETE
  RESULT: PASSED  <-- 장치가 잡지 못함
```

이는 `acceptance.md:6` 이 이 문서의 첫 줄에서 경계한다고 선언한 바로 그 형태다 — 「**기준이 이름 붙인 동작을 통째로 지워도 초록으로 남는 기준**」. R2-4 를 닫으려고 만든 기준이 R2-4 와 같은 부류를 한 겹 위에서 재현했다(D1 → R2-4 → R3-1 로 세 번째).

**한계 공시가 불완전하다.** `acceptance.md:495` 는 「마커도 선언도 없는 완전히 누락된 종속은 잡지 못한다」 하나만 적는다. 위 세 구멍 — **표 자체가 틀려도 초록** — 은 공시되지 않았다. 공시된 내용은 참이지만 **완전하지 않다.**

**정직한 반대편도 적는다**: 이 장치는 무용하지 않다. `delta`(마커 삭제)와 `beta`(펜스 마커)를 잡으므로, **현실적인 사고 — 종속 자리를 더하면서 선언을 잊는 것 — 은 실제로 걸린다.** 결함은 「장치가 아무것도 안 한다」가 아니라 「**이름과 검증 대상이 명령보다 넓다**」이다.

**필요한 수정 (택1, 둘 다 값싸다)**:
① 제목·Given·검증 대상을 명령에 맞게 좁힌다 — 「선언과 마커의 정합이 확인된다」. 그리고 「표 자체의 정확성은 이 기준이 재지 않는다」를 한계 공시에 추가한다.

**R3-2 — AC-CI-007 의 세 단언은 진단일 뿐 차단하지 못한다**
`acceptance.md:303-345` — Severity: major — Class: blocking

R2-2 가 요구한 세 단언은 정확히 들어갔다. 그러나 **그 단언이 붉어져도 절차가 멈추지 않는다.** 기준의 bash 블록에 `set -e` 가 없고, python heredoc 이 `AssertionError` 로 비영 종료해도 다음 줄부터 그대로 이어진다 — `grep -c` → `git add` → `git commit` → `git push`. 즉 **과삭제된 워크플로가 커밋되고 원격에 올라간다.**

셸 의미론을 값싸게 재현했다:

```
$ bash demo.sh
AssertionError: ('정확히 한 단계만 지워져야 한다', 5, 3)
mutation written to file
NEXT COMMAND STILL RAN (exit of previous was 1)
...and a commit/push would run here too
block exit=0
```

파일 쓰기(`p.write_text`)가 단언보다 **앞에** 있으므로, 단언이 깨진 시점에 워크플로는 이미 망가진 상태다. R2-2 의 원인(「그것만 사라졌다를 재지 못한다」)은 닫혔지만, **재고도 막지 못하는** 상태가 남았다.

**미실행 표시**: `.github/workflows/ci.yml` 은 아직 없으므로 이 절차를 실제 대상에 돌리지 못했다. 위 재현은 **셸 동작만** 보인 것이고, 「단언 실패 시 커밋까지 간다」는 그 셸 동작 + 블록의 문면에서 따라 나온다.

**필요한 수정**: 블록 첫 줄에 `set -euo pipefail` 을 넣거나, python 블록 뒤에 `|| exit 1` 을 붙인다. 한 줄이다.
