## 1. 쉬운 말 요약

카드 t13 은 겉보기에 "커버리지 스크립트 한 줄 추가"였지만, plan 단계에서 **숨은 결함이 하나 더** 드러났다. 지금 server 에서 커버리지가 측정되는 것은 server 가 도구를 가져서가 아니라, 형제 워크스페이스 `channel` 이 그 도구를 선언한 덕에 루트 `node_modules` 에서 **우연히 빌려 쓰고** 있기 때문이다. channel 이 그 선언을 빼는 순간 server 커버리지는 조용히 깨지고, 이 카드가 닫으려던 문제가 그대로 돌아온다. 그래서 SPEC 의 중심은 "스크립트 추가"가 아니라 **server 가 자기 이름으로 도구를 선언하는 것**이 됐다.

기준선을 실측한 결과 **커버리지는 이미 줄 97.01%** 로 Craft 85% 기준을 넉넉히 넘고 있었다. 4라운드 동안 "측정 불가"였던 것은 품질이 나빠서가 아니라 **잴 자가 없어서**였다.

감사는 두 라운드가 걸렸다. 1회차 FAIL 0.62 — 수용 기준 여섯 중 넷이 실행하면 터지거나, 돌아도 이 카드가 만드는 것을 재지 않았다. 개정 후 2회차 PASS 0.88 이며, 1회차 차단 7건은 **전부 감사자의 실행으로 종결**이 확인됐다.

## 4. 감사 궤적

### 1회차 — FAIL 0.62 (차단 7 · 비차단 8)

가장 심각했던 **F-01 (Critical)**: AC-003 이 "임계 게이트에 이빨이 있는지" 재는데 임계값을 **CLI 로 넘겨서** 쟀다. vitest 는 넘겨받은 값으로 판정하므로 설정 파일의 85 는 한 번도 읽히지 않고, 감사자가 실행해 보니 **설정 파일이 없는 상태에서도 이미 통과**했다. REQ-004 를 통째로 지워도 초록인 기준이었다 — 이 저장소가 반복해 데인 «아무것도 검증하지 않는 수용 기준».

나머지: F-02 `json-summary` 리포터를 요구하는 REQ 부재로 AC-002 가 실행 불가 · F-03 테스트 코드 임포트 누락으로 즉사 · F-04 `git diff --name-only` 가 미추적 신규 파일을 못 봐 올바른 구현을 거짓 실패 · F-05 닫힌 질문이 17군데에 열린 것으로 남음(두 자리는 "한 곳에만 있다"고 자기 반증) · F-06/F-07 조항 수준 누락 둘.

주요 실행 증거:
- **F-01**: 설정의 `lines` 를 98 로 올려 오버라이드 없이 실행 → `exit 1` + `ERROR: Coverage for lines (97.01%) does not meet global threshold (98%)`. 85 로 되돌려 → `exit 0`. 이제 설정 파일 없이는 통과할 수 없다.
- **F-03**: 아무도 돌린 적 없던 회귀 짝 코드를 **문서에서 그대로 추출**해 실행 → 일곱 단언 전부 통과. 문서가 지정한 변이 셋이 각각 겨냥한 단언을 **정확히 하나씩** 실패시켰고, 매번 실패 테스트는 그 하나뿐이었다.
- **F-06**: 문서가 변이를 지정하지 않은 주석 검사(단언 7)를 감사자가 자체 판단으로 시험 → 주석 3줄 삭제 시 그 테스트만 실패. 조항에 이빨이 있다.

**부수 성과 — 미해결 질문 하나가 해소됐다.** "테스트가 실패해도 vitest 가 임계 검사를 하는가"의 답은 **아니오**다(vitest 4.1.11: 커버리지 보고서 자체를 찍지 않고 임계 판정도 건너뛴다). 따라서 개정본이 넣은 `--exclude` 우회는 방어적 군더더기가 아니라 **없으면 AC-003 관측 1 이 성립하지 않는 필수 장치**다. 이 사실을 `plan.md` §E 에 근거와 함께 기록해, 나중에 "군더더기 아닌가"로 읽혀 제거되는 것을 막았다.

## 6. Gaps — plan 단계가 관측하지 **않은** 것

1. **`npm install` 후 `package-lock.json` 의 실제 변경 규모** — 두 감사 모두 잠금 파일을 건드리지 않으려 설치를 생략했다. run 단계 몫.
2. **`npm test -w channel`(형제 무회귀)** — 두 감사 모두 돌리지 않았다.
3. **run 레인 세션이 이 세션과 동일한 격리 가드를 받는지** — NEW-01 의 거부는 이 워크트리의 감사·편집 세션에서 재현됐고 run 레인도 같은 워크트리에서 돌지만, 그 세션의 가드는 직접 관측하지 않았다. 교정된 형태는 어느 쪽에서도 안전하다.
4. **관측 3 이 코드 산출물 4개가 실제로 있는 상태에서 네 줄을 내는지** — 합성 입력으로만 확인했다(실제 파일 생성은 트리 오염). run 단계 단계 8 이 실측한다.
5. **`.moai/reports/t7/sync-audit.md` §T5** — t7 워크트리에 있어 세 세션 모두 읽지 못했다. 다만 이 SPEC 의 요구사항은 운영자 결정 D1·D2 와 이 워크트리 실측에서 나오므로 그 보고서 내용에 의존하지 않는다.

## 7. Residual-risk

- **`FILE_COUNT=11` 은 다음 카드가 `server/src/` 에 파일을 더하는 순간 거짓 실패한다.** 사유·갱신 책임을 `acceptance.md` 본문에 적었으나, 그 책임은 아직 존재하지 않는 카드에 지운 것이라 이 SPEC 이 강제할 수단이 없다. 의식적으로 치른 대가.
- **단언 6 은 `pkg.devDependencies.vitest` 의 존재를 전제**한다. 그 선언이 사라지면 계약 위반이 단언 실패가 아니라 `TypeError` 로 드러난다.
- **`--exclude` 는 프로브 시점에 계약 테스트가 존재할 때만 의미가 있다** — NEW-02 교정(재프로브)이 이를 보장하나, 단계 순서를 나중에 누가 바꾸면 다시 공허해진다.

1. **`npm install` 이 선행돼야 한다** — 이 워크트리는 새로 만들어져 `node_modules` 가 없었고, plan 단계가 루트에서 설치했다(233 패키지, exit 0). run 레인이 새 세션이면 다시 필요할 수 있다.

4. **커버리지를 올리려 소스·테스트를 고치지 않는다** — 이 카드는 재는 도구를 들이는 것이지 숫자를 올리는 것이 아니다(REQ-COVERAGE-007).
