# M5 억제 미탐지 공백 공시 — SPEC-GWAUTH-002 (카드 t22) run 단계 기록

이 문서는 R3-ii 지시에 따라 «선택적 억제(selective suppression) 미탐지» 공백을 기준 저작과
공시에 반영한 자리를 기록한다. 탐지 기제 자체는 만들지 않았다(리드 R3-ii).
**처분: 운영자 확인(2026-08-30) 결과 탐지 카드를 등록하지 않기로 확정 — 공백은 spec.md §0-7 과
본 기록으로만 유지된다.** 아래는 공백이 «글로 남은» 자리들이다.

## 공백의 정의 (spec.md §0-7·§5, acceptance.md 잔여 위험)

경로에 선 상대는 유효한 봉투를 **흔적 없이 삼킬 수 있고**, `seq` 는 재생은 막지만 **삭제를
탐지하지 못한다**. 받는 쪽 seq 규칙은 «직전값보다 크면 받아들인다» — 건너뛴 번호(삭제)가
있어도 다음 유효 봉투는 정상 도착한다. 이로써 삭제가 반복돼도 채널은 계속 살아 있고,
사용자는 «일부 메시지가 조용히 사라지는» 상태로 남는다.

## 기준 저작에 반영된 자리

1. **AC-GWAUTH2-015 본문** (channel/test/transport-auth.test.ts 의 it 본문 주석) — «받는 쪽은
   이하만 거절한다 — 건너뜀(삭제)을 탐지하지 않는 것이 이 설계의 공시된 한계다 (spec.md §0-7)».
   클라이언트 구현(channel/src/gateway-client.ts lastSeq 주석)에도 같은 문장이 있다.
2. **AC-GWAUTH2-014** — 변조 봉투·역행 봉투·봉투 없는 프레임이 모두 버려짐을 재지만, «삼켜짐»
   (아무것도 도착하지 않음) 은 이 문서의 기준 어디에서도 재지 않는다 — acceptance.md §0-7 이
   공시한다. 본 시험은 이 공백을 메우지 않았다.
