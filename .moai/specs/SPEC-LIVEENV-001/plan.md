# SPEC-LIVEENV-001 — 구현 계획

## §A 맥락

카드 `t35`(Class C)는 `SPEC-LIVEVERIFY-001` §A 회고에서 나왔다. 그 §A 는 완주했으나 같은 부류의 사고가 반복됐고(기본 체크아웃 기동 2회 · 재초대로 토큰 무효화 2회 · 낡은 토큰 3회 · 전역 MCP env 의 숨은 토큰 · 캡처 재촬영 2회), 뿌리는 「환경이 사람의 기억 속에 있다」 하나다. 이 카드는 그 환경을 스크립트와 추출기로 옮긴다.

**이 계획이 바꾸지 않는 것**: `SPEC-LIVEVERIFY-001` 의 요구사항·수용 기준·증거. 그 SPEC 은 `completed` 이며 이 저장소는 완결된 SPEC 을 소급 개정하지 않는다.

```bash
npm install
```

## §D 제약

### D-1 저장소 밖 무편집

`~/.claude.json` · `~/.claude/settings.json` · 셸 기동 파일은 **읽기 전용**이다. 훑기의 대상이지 수정 대상이 아니다.

### D-2 `SPEC-LIVEVERIFY-001` 무편집

`evidence/` 를 포함해 그 디렉터리 아래 어떤 파일도 쓰지 않는다. 추출기의 기본 산출 경로는 **이 SPEC 자신의** `evidence/` 이며, `--out` 으로 바꿀 수 있게 만들어 나중에 다른 SPEC 을 겨눌 수 있게 한다.

### D-3 `scripts/` 아래 문언 제약

`AC-E2E-016` 의 **다섯** 측정 가운데 **넷**(①·①-b·①-c·②)이 `scripts/` 를 훑는다(다섯째 ③ 은 `README.md` 의 체크리스트 절 조건부라 이 카드에는 「해당 없음」). 새 파일에서 금지되는 것:

- `anthropic` · `claude.ai` · `api.anthropic` 문자열, 그리고 `spawn('claude'` / `spawn("claude"` 형태
- 「수동 검증(을) 수행/완료」 · 「실 세션으로 확인/검증」 · 「사람이 (직접) 확인했」 류의 **주장 문장** (주석 포함)
- `AC-016-EXEMPT` 표지 (측정 ①-c 가 `scripts/` 에서 이 표지의 합을 `0` 으로 못박는다)

셸 스크립트가 `exec claude …` 로 세션을 띄우는 것은 위 패턴에 걸리지 않는다. 그러나 **얇은 여유**이므로 `AC-LIVEENV-016` 이 착지 후 네 측정을 재실행해 확인한다.

### D-4 예행은 `scripts/e2e.mts` 안에 넣지 않는다

`REQ-E2E-007` 이 시나리오를 열다섯으로 못박고 `[n/15]` 표지를 기준으로 쓴다. 헬퍼는 상대 import 로 가져다 쓰되 시나리오 수와 표지는 건드리지 않는다.

### D-5 사람 손이 남는 자리를 줄였다고 적지 않는다

카드의 목표는 「승인 클릭 · `/clear` · 최종 눈검사」 셋이었다. **실측이 넷째 자리를 드러냈다** — 봇 세션 첫 기동의 MCP 항목 승인(F-12 · `⏸ Pending approval`). 그중 `/clear` 는 세션 위생이 아니라 **`AC-LIVEVERIFY-008` 의 시험 단계**다.

**[HARD] 종결 보고는 셋이 아니라 넷에서 출발한다**(DoD 9). 실제로 남은 사람 손을 전건 열거하고, 넷보다 늘었다면 늘어난 것도 적는다. **줄이지 못한 것을 줄였다고 적지 않는다** — 카드가 「셋」이라고 적었다는 사실은 목표의 기록이지 달성의 근거가 아니다.

## §E 자기 검증

각 마일스톤은 끝날 때 자기 기준의 증거 파일을 만들고, **변이를 함께 실행**해 그 기준이 빨개지는 것을 본다. 변이 없이 초록만 보고하면 그 기준이 상수 함수인지 알 수 없다.

### E-1 plan 단계에서 닫지 못한 것 — 어느 방향으로도 단정하지 않는다

아래 넷은 **스크립트가 아직 없어서** plan 단계가 잴 수 없었던 값이다. 「잴 수 없었다」를 「없다」나 「괜찮다」로 옮기지 않는다 — 각 행은 그것을 닫는 run 단계 증거를 지목하고, **그 증거가 나오기 전까지 미결로 남는다.**

### M0 — 스크립트 뼈대: 트리 고정과 `up`/`down` 생애주기 (우선순위 High · 의존상 첫 자리)

`status` 를 걸 자리를 만드는 단계다. 결정의 무게는 M1 이 지고, 이 단계는 그 결정이 놓일 뼈대를 세운다.

- `scripts/live-env.sh` 를 만들고 `git rev-parse --show-toplevel` 로 자기 트리를 확정한다. 호출자의 cwd 에 의존하지 않고 `cd` 로 그것을 바꾸지도 않는다(REQ-001).
- `paths` 하위 명령이 서버·데이터·봇·채널 `dist` 경로를 **`key=value` 한 줄씩** 찍는다. **이 형식이 `AC-LIVEENV-001` 의 분모를 만든다** — 형식이 없으면 「출력된 경로 줄 수」를 사람이 세게 된다.
- `up` 이 빈 포트를 잡아 서버를 띄우고 포트·데이터 디렉터리·봇 파일 뿌리·pid 를 상태 파일 한 곳에 적는다. `down` 은 그 pid 만, 그리고 그것이 이 트리의 서버일 때만 종료한다(REQ-002).
- 산출: `AC-LIVEENV-001`·`AC-LIVEENV-002` 증거(`E01-tree-pin.txt`·`E02-lifecycle.txt`) + 변이 ①.

### M1 — `status` 의 3값 계약 (우선순위 High · 가장 되돌리기 어려움)

이 카드의 중심 결정이다. `status` 가 무엇을 「잴 수 없었다」로 부르는지가 정해지면 나머지가 따라온다.

- 세 축의 판정 형태를 확정한다: `listen_pid_cwd=` · `db_rows=` · `principal=`.
- **측정 불가**의 정의를 축마다 적는다 — 도구 부재(`lsof`) · pid 판독 실패 · DB 파일 부재 · 초대 목록 조회 실패.
- 종료 코드 `0`/`1`/`2` 를 확정하고, `2` 가 나오는 **모든 경로를 스크립트 자신이 `status --unmeasured-paths` 로 찍게** 한다. 그 출력이 `AC-LIVEENV-004` 의 **분모**다 — 실걸이할 경로를 문서가 손으로 골라 적으면 전칭이 아니라 표본을 잰 것이 된다.
- **부분 측정을 그 목록에 넣는다** — 도구는 있으나 값을 얻지 못한 상태(`lsof` 는 있으나 pid 의 cwd 를 못 읽음 · DB 파일은 있으나 대상 테이블이 없음 · 초대 목록이 `200` 이되 비어 있음). **`0` 이 새는 자리는 「도구가 아예 없다」가 아니라 여기다.**
- 엣지 케이스 `E-1`·`E-2`·`E-3`·`E-5` 의 이름도 그 목록에 있어야 한다 — 넷 다 「재지 못함」이다.
- 음성 대조군을 실제 사고 형태로 재현한다(같은 포트를 무관한 프로세스가 점유).
- 산출: `AC-LIVEENV-003`·`AC-LIVEENV-004` 증거 + 변이 ②.

**[처분됨 — `principal` 축은 두 면을 함께 읽는다]** 후보는 둘이었다 — (a) 방의 초대 목록 `online` 필드(웹 API 를 거친다) (b) `lsof … ESTABLISHED` 의 확립 접속 목록(API 를 거치지 않는다). **리드 처분: 둘 다 읽는다.**

근거 둘.

1. **형제 기준이 이미 그렇게 판정했다.** `AC-LIVEVERIFY-012` 는 둘 다 필요하다고 적었다 — ㉠㉡ 이 API 표면이고 ㉢ 이 접속 표면이다. 한 면만 읽으면 그 판정을 만족시키지 못하는 증거가 나온다.
2. **`online` 하나로는 갈리지 않는 것이 있다.** 그 필드는 게이트웨이의 `isOnline(roomId, botId)` 를 그대로 내보내고(`server/src/routes-bots.ts:103`), 그 함수는 그 방·그 봇으로 붙은 소켓이 **하나라도** 있으면 참이다(`server/src/gateway.ts:355-358`). 방과 봇은 가르지만 **어느 프로세스가 붙었는지는 말하지 않는다** — 「이 실행이 띄운 봇 세션이 붙었다」와 「그 봇의 자격을 쥔 **다른** 프로세스가 붙었다」가 같은 `true` 로 나온다. 낡은 토큰을 쥔 리드 세션이 봇 자격으로 붙어 t32 의 측정을 오염시킨 것이 정확히 그 형태다. `conn=`(확립 접속 수)이 그 자리에 프로세스 면을 놓는다.

**치르기로 한 값**: `status` 가 무거워지고, `lsof` 가 없는 환경에서 `2`(재지 못함)로 끝나는 경로가 넓어진다. **그 확장은 옳은 거동이지 회귀가 아니다** — 못 잰 것을 못 쟀다고 말하는 자리가 늘어난 것이다.

**세 자리를 함께 고쳤다**: `spec.md` REQ-003 ㉢ · `acceptance.md` AC-003 Then · 이 절. 특히 `acceptance.md` 의 `principal=` **형식 문자열**이 두 축을 실제로 담는지 확인했다 — `principal=<봇이름>:api=<online 불리언>:conn=<확립 접속 수>` 이다. v0.1.0 의 `principal=<봇이름:online 여부>` 는 한 면만 담을 수 있어, **형식이 결정을 조용히 되돌리는** 자리였다(1회차 감사 D2).

### M2 — 토큰의 자리와 주입 통로 (우선순위 High)

- 토큰 파일의 경로는 **`data/live-env/token`**(권한 `0600`)으로 **확정됐다**(아래 처분).
- `invite` 가 발급 응답의 평문을 그 파일에 넣고 표준출력에는 앞 8글자만 남긴다. **표준출력의 형식은 `key=value` 두 줄로 못박는다** — `token_head=<앞 8글자>` · `issued_at=<발급 시각>`(REQ-005). 값만 줄줄이 찍으면 `AC-005` ㉣ 이 「처음 나온 `[0-9a-f]{8}`」으로 토큰을 골라야 하는데, `20260906` 같은 시각 표기가 같은 패턴에 걸려 **판정이 출력 순서에 걸린다**(2회차 감사 B-4). M0 의 `paths` 에 건 것과 같은 규율이고, 같은 이유다 — **이름표가 있으면 위치를 세지 않아도 된다.**
- `bot` 이 그 파일을 읽어 **자식 환경으로만** 넘긴다.
- §7 의 열두 자리를 `token-sweep` 으로 내린다. 자리 이름을 `site=<이름>` 으로 찍어 **이름 집합**으로 대조한다(개수 대조는 쓰지 않는다).
- 산출: `AC-005`·`AC-006`·`AC-007`·`AC-008` 증거 + 변이 ③·④.

**[처분됨 — 토큰 파일은 `data/live-env/token`, 권한 `0600`]**

근거 둘.

1. **`.gitignore` 편집이 필요 없다.** `data/` 는 이미 `.gitignore` 2행에 있다. 실측: `git check-ignore -v data/live-env/token` → `.gitignore:2:data/` · `exit=0`. 새 디렉터리 + `.gitignore` 한 줄이라는 대안은 편집 없이 얻을 수 있는 것을 편집으로 얻는 형태였다.
2. **부작용이 의도다.** 데이터 디렉터리를 통째로 지우는 정리 절차가 토큰도 함께 지운다 — 그것을 **원한다**. t32 의 사고 부류가 「낡은 토큰을 3회 다시 썼다」였고, 데이터와 토큰이 함께 죽으면 낡은 토큰이 살아남아 다시 쓰일 자리가 없다. 즉 정리가 곧 토큰 무효화이며, 그 결합이 이 카드가 겨눈 사고를 구조적으로 막는다.

### M3 — 봇 세션 전용 적재 경로 (우선순위 High)

- 봇 작업 디렉터리 **`<wt>/bot-01`** 에 `.mcp.json` 을 쓴다 — 토큰 없음, 이 트리의 `channel/dist/index.js`, 이 실행의 `MINIDISCORD_SERVER`.

- **첫 기동의 승인 대기를 알린다.** `bot` 은 프로젝트 범위 MCP 항목이 `⏸ Pending approval` 로 뜬다는 사실을 표준출력에 적는다(F-12).

**[처분됨 — 봇 작업 디렉터리는 `<wt>/bot-01`(워크트리 안)]**

근거 셋.

1. **카드의 트리 고정 요구와 일관된다.** 이 카드의 중심 요구(REQ-001)가 「모든 경로를 이 트리의 뿌리에서 유도한다」이고, 봇 디렉터리만 저장소 뿌리로 빠지면 그 규칙에 예외가 하나 생긴다.
2. **워크트리를 폐기하면 봇 디렉터리도 함께 사라진다.** 다음 카드가 물려받을 잔여가 남지 않는다. 형제 SPEC 은 `<repo>/bot-01` 을 썼고, 그 경로는 워크트리 폐기 후에도 남는다.
3. **대가는 `.gitignore` 한 줄이다.** 위 작업 항목에 명시했다.

**[처분됨 — 실측했다: 저장소가 아닌 디렉터리의 `.mcp.json` 도 적재된다]**

이 표지는 다른 셋과 성질이 달랐다. 셋은 선택지가 둘 이상이고 어느 쪽도 명백히 옳지 않은 **진짜 결정**이었지만, 이것은 **참·거짓이 정해져 있는 사실**이었다 — 결정으로 분류해 유예하면 run 단계에서 plan 산출물을 다시 쓰게 되는 자리였다(1회차 감사 D1). 그래서 plan 단계에서 쟀다.

- **실행**: 저장소가 **아닌** 빈 디렉터리(`/private/tmp/claude-501/mcp-probe-t35/`)를 만들어 stdio 서버 하나(`liveenv-probe`)를 선언한 `.mcp.json` 을 쓰고, 그 디렉터리를 cwd 로 `claude mcp list` 를 실행했다.
- **관측(전문 두 줄)**:
  ```
  liveenv-probe: node -e setInterval(()=>{},1e9) - ⏸ Pending approval (run `claude` to approve)
  minidiscord-channel: node /Users/byunjungwon/Dev/my-project-04/minidiscord/.claude/worktrees/t32/channel/dist/index.js - ✘ Failed to connect — CONNECTION_CLOSED: Connection closed
  ```
- 탐침 디렉터리는 관측 후 제거했다. 인용하는 것은 **이 실측**이지 살아 있는 산출물이 아니다.

**따라 나오는 것 둘. 둘 다 계획에 실었다.**

**(a) 전제가 섰다 — 대안 분기를 뺀다.** `liveenv-probe` 가 목록에 뜨므로 적재는 **된다**. `spec.md` §3 D5 와 `REQ-LIVEENV-009`·`AC-LIVEENV-009` 가 그 위에 그대로 선다. 「적재되지 않으면 (b) `--mcp-config <파일>` 로 간다」던 대안 분기는 **측정이 닫았으므로 계획에서 뺐다** — 살려 두면 닫힌 물음이 열린 채로 보인다. (전역 항목을 고치는 선택지는 애초에 없었다 — 운영자 결정.)

**(b) 카드가 셈하지 않은 사실이 하나 나왔다 — 사람 손은 셋이 아니라 넷이다.** 항목의 상태가 `⏸ Pending approval` 이다. 프로젝트 범위 `.mcp.json` 서버는 **첫 사용에 사람 승인**을 요구하므로, **봇 세션은 첫 기동에서 무인으로 채널에 붙지 않는다.** 카드는 남는 사람 손이 「승인 클릭 · `/clear` · 최종 눈검사」 셋이라고 적었지만 **넷이다.** 이 사실이 실린 자리:

- `spec.md` §3 D1 6행(카드 문언 정정) · §6 위협 모형 · §1.2 F-12
- `REQ-LIVEENV-009` — `bot` 의 알림 의무
- `AC-LIVEENV-009` — 승인 전 왕복 부재는 **실패가 아니라 미관측**
- `AC-LIVEENV-014` · §D-5 · DoD 9 — 사람 손 열거의 넷째 자리

**[HARD] 어떤 기준도 「봇이 무인으로 첫 접속에 성공한다」를 전제해서는 안 된다.**

- 산출: **`AC-LIVEENV-009` 증거(`E09-mcp-attribution.txt`)** + **`AC-LIVEENV-010` ㉡ 의 절반**(`E10-extract-run.txt` 의 실 세션 실행분) + 변이 ⑤ 의 실행. 두 파일의 실 세션 절반에는 **그 세션의 UUID** 를 적는다 — DoD 1 이 그것으로 「M8 을 실제로 돌렸는가」를 판정한다. 파일이 있다는 사실만으로는 셈하지 않는다.

| `A01 ㉣` 를 **한 면만** 뽑고 `judge: machine` 을 붙인다 | 형제 기준은 두 면의 **일치**를 요구한다. 만족시키지 못하는 증거에 기계 판정이 달린다 |
| `scripts/` 새 파일 주석에 「실 세션으로 확인」류 문구를 쓴다 | 형제 기준을 빨갛게 만든다(§D-3) |
