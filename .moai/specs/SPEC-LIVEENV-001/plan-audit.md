지시받은 여덟 부류를 기준 16건 전부에 대고 확인했다. 걸린 것은 위에 적었고, **걸리지 않은 것**을 여기 남긴다 — 「무엇을 검사했는가」가 「무엇이 실패했는가」보다 정보가 많기 때문이다.

1. **위조자가 실제 공격자보다 약한가** — `AC-003` 의 음성 대조군은 합성이 아니라 **실제로 일어났던 사고**(무관한 프로세스가 같은 포트 점유)를 재현한다. 원문 확인: `SPEC-LIVEVERIFY-001/progress.md:135` 에 "포트 3000 에는 무관한 remotion 프로세스(94851)가 `*:3000` 을 잡고 있어, **서버 생존을 응답 코드로 판정하지 말 것**" 이 실재한다. 인용이 사실이며 대조군이 실제 사고보다 약하지 않다. **통과.**
2. **셸로만 재는 기준** — `AC-010`·`AC-012` 가 인프로세스 회귀(`server/test/live-extract.test.ts`)를 짝으로 갖고, `acceptance.md:172` 가 그 이유("추출기 본문을 통째로 지워도 「파일이 있다」는 셸 검사는 이전 실행의 산출로 초록일 수 있다")를 명시했다. **통과.** 다만 도달성 쪽에 D10 이 남는다.
3. **부재 주장의 대기 상한 + 양성 대조군** — 대기 상한 120초가 공통 하네스(`acceptance.md:25`)에 있고, 양성 대조군은 `AC-002`(살아 있는 무관 프로세스)·`AC-003`·`AC-008`(봇이 실제 접속 중인 시각)·`AC-011`(가짜 hex)·`AC-013`(Playwright 가 있는 실행)에 각각 있다. **AC-005 만 빠졌다 → D7.**
4. **판별자가 상수 함수인가 · 변이가 절반을 가르는가** — 변이 여섯(①~⑥)이 각각 자기 기준을 겨눈다. 특히 변이 ②(3값 분기 삭제)는 축 셋을 한 번에 지우지만, `AC-004` 가 축마다 **따로** 실행 셋을 요구하므로 어느 축이 재어졌는지가 갈린다 — 굵은 변이가 절반을 가리는 형태가 아니다. **통과.**
5. **`exit 0` 이 「찾지 못함」과 「통과」를 섞는가** — `status` 표면에서는 REQ-004·AC-004 가 이것을 정면으로 닫는다. 그러나 **모든 미측정 경로가 `2` 로 가는가**라는 물음에는 아니라고 답해야 한다: REQ-004 가 열거한 미측정 사유는 넷(도구 부재·pid 판독 불가·DB 파일 부재·초대 목록 조회 실패)이고 AC-004 는 그중 셋을 실걸이한다. 더 중요한 것은 **부분 측정**이다 — `lsof` 가 있고 실행되지만 cwd 를 못 읽는 경우, DB 파일은 있으나 테이블이 없는 경우, 초대 목록이 200 으로 오되 비어 있는 경우는 어느 기준도 겨누지 않는다. 그리고 `E-1`(포트를 그 사이 남이 가져감 → `2`)은 엣지 케이스 표에만 있고 AC 가 없다. **부분 관측 상태가 `0` 을 낼 수 있는지는 이 SPEC 으로는 판정 불가 — 격차(gap)로 남긴다.** 추가로 추출기 표면에는 계약 자체가 없다 → D9.
6. **회귀 스위트 밖의 기준** — `AC-010`·`AC-012` 는 `npm test` 안에 들어가고(품질 게이트 `:257`, DoD 4), 나머지는 증거 파일 기반이다. `AC-001`~`AC-009`·`AC-013`~`AC-016` 은 스위트 밖이지만 이들은 셸·프로세스·git 관측이라 인프로세스로 옮길 대상이 아니다. **통과.**
7. **관용구 훑기 대 어간 훑기** — `AC-007` 이 개수가 아니라 **이름 집합** 대조를 [HARD] 로 못박은 것이 정확히 이 부류의 처방이다. 방향은 옳다. 다만 그 처방을 실행할 명령이 없다 → D4.
8. **두 번째 출처 없는 수치** — 이 SPEC 이 못박은 수 셋을 직접 재측정했다.
   - `AC-016` 의 네 값 — **이 나무에서 직접 실행해 확인했다**:
     ```
     $ grep -rEn "수동 검증(을)? ?(수행|완료)|실 세션으로 (확인|검증)|사람이 (직접 )?확인했" README.md scripts/ .moai/specs/SPEC-E2E-001/ | grep -v 'AC-016-EXEMPT'; echo "exit=$?"
     exit=1
     $ grep -rE "..." README.md scripts/ .moai/specs/SPEC-E2E-001/ | grep -c 'AC-016-EXEMPT'
     7
     $ grep -rc 'AC-016-EXEMPT' README.md scripts/
     README.md:0
     scripts/e2e.mts:0
     $ grep -rEn "anthropic|claude\.ai|api\.anthropic|spawn\(['\"]claude" scripts/ ; echo "exit=$?"
     exit=1
     ```
     **착지 전 기준선이 초록임을 실측으로 확인했다** — `AC-016` 은 존재하는 초록에서 출발한다. (범위 서술의 오류는 별개다 → D12.)
   - `AC-016-EXEMPT` 표지가 이 SPEC 자신의 `plan.md:53`·`acceptance.md:232` 에 각 1건 있으나, 측정 ①-c 의 범위가 `README.md scripts/` 뿐이고 ①-b 의 범위가 `README.md scripts/ .moai/specs/SPEC-E2E-001/` 뿐이라 **이 SPEC 의 파일은 어느 측정에도 걸리지 않는다.** 실행으로 확인했다(위 ①-c 출력에 이 SPEC 경로 없음). 결함 아님.
   - `plan.md:55` 의 "셸 스크립트가 `exec claude …` 로 세션을 띄우는 것은 위 패턴에 걸리지 않는다" — 패턴 넷(`anthropic`·`claude\.ai`·`api\.anthropic`·`spawn\(['\"]claude`) 어느 것도 `exec claude …` 를 잡지 못한다. **판단이 옳다**, 그리고 "얇은 여유"라고 스스로 적고 `AC-016` 으로 착지 후 재실행하게 한 것도 옳다. **통과.**
   - `spec.md` §7 표 12행 — `awk` 로 실측 12 확인. 표 자체는 옳고, 그것을 세는 명령이 틀렸다 → D4.

## `ps eww` 잔여를 「양성 대조군」으로 바꾼 것에 대한 판정

**정직한 잔여 공시다 — 실패할 수 없는 기준이 아니다.** 근거 셋.

1. `AC-006` ㉡ 은 실제로 빨개질 수 있다: `bot` 이 세션을 띄우지 못하거나 토큰을 자식 환경에 넣지 못하면 `ps eww` 에 값이 없고 그 절은 실패한다. 상수 함수가 아니다.
2. 잔여를 닫았다고 **주장하지 않는다**: `REQ-008`(`spec.md:89`)이 "닫는 것은 캡처·이력·커밋 세 통로"라고 범위를 좁혔고, `spec.md:196` 위협 모형 표가 이 통로를 **「막히는가: 아니오」**로 적었으며, §5 에 `### Out of Scope — ps eww 통로 차단` 절이 소유 SPEC(`SPEC-CHANWIRE-001`·`SPEC-CHANAUTH-001`)까지 지목한다. 세 자리가 같은 것을 말한다.
3. 근거가 코드에 있다: `channel/src/index.ts:121` 을 직접 읽어 `const token = process.env.MINIDISCORD_TOKEN` 이고 argv 경로가 없음을 확인했다. 환경변수가 유일한 통로인 이상 같은 사용자의 `ps eww` 는 원리적으로 읽는다 — 이 카드가 닫을 수 없다는 주장이 사실이다.

남는 것은 D13 하나(개선이 이 기준을 빨갛게 만드는 방향)이고, 그것은 지금 고칠 사안이 아니다.

## 합성 fixture + 실 세션 한 번이 매핑을 세우는가

**부분적으로만 세운다.** `acceptance.md:171` 이 "합성 fixture 는 대응 관계만 세운다 — 도달성은 따로 잰다"고 옳게 갈랐고 도달성 자리를 둘 지정한 것도 옳다. 그러나 그 둘 중 하나(예행)는 대화 기록 표면에 원리적으로 닿지 못하고, 다른 하나(실 세션)는 AC 도 증거 파일도 없는 M8 에 걸려 있다 → **D10 + D5.** 현재 문언대로면 「실제 경로가 한 번도 밟히지 않은 채 `AC-010` 이 초록」인 상태가 성립 가능하다.

## 확인하지 못한 것 (격차 — 어느 방향으로도 단정하지 않는다)

1. **부분 측정 상태가 `status=0` 을 낼 수 있는가** — 스크립트가 아직 없으므로 코드로 확인할 수 없고, SPEC 문언은 전칭("세 축 중 어느 하나라도 측정 자체가 성립하지 않으면")으로 옳게 적혀 있으나 그 전칭을 재는 기준이 셋뿐이다. 실패한다고도 통과한다고도 말할 수 없다 — run 단계가 `2` 로 가는 모든 경로를 열거해야 판정 가능하다(`plan.md:83` 이 이미 그것을 M1 의 작업으로 적었다).
2. **저장소 밖 디렉터리의 `.mcp.json` 적재 여부** — 이 감사는 세션을 띄우지 않았으므로 재지 않았다. D1 의 핵심.
3. **`AC-014` 의 「기대한 파일 집합」** — 어디에도 열거돼 있지 않아 예행이 무엇을 만들면 통과인지 판정할 수 없다.
4. **`M01-mutation.txt` 변이 여섯의 실효성** — 변이 대상 코드가 아직 없으므로 각 변이가 실제로 그 기준만 빨갛게 하는지는 run 단계에서만 확인된다. 문언 수준에서는 축별로 갈려 있어 합격 방향이다.
