## ── [정정] 수정 시각 두 값은 판정에 쓰지 않는다 ──────────────────────
# 위 두 줄에 원래 「두 값이 같으면 이 카드가 그 파일을 편집하지 않았다는 뜻이다」라는
# 주석이 붙어 있었다. 그 주석을 정정한다. 두 가지가 함께 틀렸다.
#   ① 그 판별자는 AC-008 이 [HARD] 로 명시적으로 «반증» 한 것이다 — 그 파일은 Claude Code
#      자신이 세션 기동·종료 때 쓰므로, 시각은 「항목이 바뀌었다」가 아니라 「세션이 떴다」를 잰다.
#      그리고 이 카드의 bot 단계가 정확히 세션을 띄우므로 정상 실행이 늘 빨개진다.
#   ② 그리고 위 두 값은 애초에 «같지 않다»(1788630392 ≠ 1788630396). 주석이 요구한 조건이
#      기록된 값 자신에 의해 성립하지 않는다.
# 두 값을 지우지는 않는다 — 지우면 「왜 이 판별자를 쓰지 않는가」가 사라진다. 참고값으로 남긴다.
# 판정선은 아래 sync 회차의 «항목 내용 대조» 다.

## ── sync 회차 (head=0a88b77) — 리드 처분 34 로 실행한 [HARD] 측정 ────
# [왜 이 절이 필요했나] AC-008 은 acceptance.md 의 측정 블록에서 «항목 내용 대조» 를 [HARD] 로
#   요구하는데, run 회차의 이 파일에 그 측정이 «한 줄도 없었다». 감사가 grep 으로 찾아냈다:
#     $ grep -c 'entry-unchanged' E08-ambient-sweep.txt   → 0
#     $ grep -c 'entry-unchanged' M01-mutation.txt        → 3   (대조군 — 이 grep 은 대상을 찾는다)
#   §E.2 의 AC-008 행은 「전역 항목 내용 불변」이라 적었으나 그 관측이 인용된 파일에 없었다.
#   주장의 내용은 참이었지만 «재지 않고 적힌» 상태였다. 아래가 실제로 잰 것이다.

## ── [미검증 ②] 양성 대조군이 반대쪽에 서 있다 — 이 회차가 닫지 못했다 ──
# AC-008 의 Given 은 「봇 세션이 떠 있고 토큰이 «실제로 쓰이는 중»」이고, [HARD] 로
#   「양성 대조군이 같은 파일에 있어야 한다 — 봇이 붙어 있지 않은 시각의 「0건」은
#    「상시 소재에 없다」와 「토큰이 아예 없다」를 가르지 못한다」를 요구한다.
# 그런데 run 회차가 기록한 principal 줄은 «api=false:conn=0» 이다 — 붙어 «있지 않은» 시각이다.
#   붙어 있던 관측은 존재하지만(E09-mcp-attribution.txt 의 `principal=pm:api=true:conn=1`)
#   그것은 다른 파일·다른 시각이라 [HARD] 의 「같은 파일」 요구를 채우지 못한다.
# sync 회차에 다시 세우려 했으나 서버가 내려가 있어 불가능했다:
$ scripts/live-env.sh status
listen_pid_cwd=- measured=no
unmeasured_path=listen_no_listener
db_rows=- measured=no
unmeasured_path=db_file_absent
principal=- measured=no
unmeasured_path=principal_state_incomplete
# exit=2  ← 3값 계약대로 「재지 못함」이다. 통과도 실패도 아니다.
#
# 이 대조군을 세우려면 봇 세션이 실제로 접속해 있어야 하고, 그것은 spec.md §1.2 F-12·F-15 가
# 열거한 «사람 손 다섯» 을 다시 밟아야 한다(MCP 항목 승인 · --dangerously-… 확인 창 포함).
# 무인으로 세울 수 없으므로 이 회차는 «미검증» 으로 남긴다 — 통과로 옮기지 않는다.
# 즉 이 파일이 오늘 세우는 것은 「훑기가 전역 항목을 편집하지 않았다」까지이고,
# 「0건이 아무도 안 쓰기 때문이 아니다」는 아직 서지 않았다.
