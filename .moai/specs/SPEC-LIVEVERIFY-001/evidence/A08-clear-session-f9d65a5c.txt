A08 (AC-LIVEVERIFY-008) — 면 2: `/clear` 가 실제로 세션을 갈랐다는 기록 증거
카드 t32 / SPEC-LIVEVERIFY-001 · 관측 2026-09-03 (레인 직접 실행, 읽기 전용)

조항은 캡처 둘(`A08-clear-terminal.png` · `A08-clear-recover.png`)을 요구하며 이 파일은
그 위에 얹는 **보강 면**이다. 캡처는 「`/clear` 를 쳤다」와 「봇이 이전 주제를 답했다」를
보이지만, **그 사이에 세션이 실제로 갈렸는지**는 화면 밖 사실이라 기록이 진다.

── ㉠ 새 대화 기록 파일이 생겼다 ──

  옛 세션 5366bfce-3324-430c-a9db-a436bb2bc79c.jsonl   (A01 ㉣ 가 쓰는 그 파일)
  새 세션 f9d65a5c-0446-4bee-bf7b-6f8a82e055d0.jsonl   64행 — `/clear` 가 만든 것

  Claude Code 는 세션마다 기록 파일을 하나 남기므로, 파일이 갈렸다는 것 자체가 맥락이
  갈렸다는 뜻이다. 옛 파일에는 이 왕복의 기록이 없다.

── ㉡ 새 세션이 `fetch_history` 를 실제로 호출했다 ──

  line 30  2026-09-03T05:21:09.069Z  tool_use  mcp__minidiscord-channel__fetch_history  {"limit":60}
  line 32  tool_result — 이력 JSON (11,494자)
  line 52  2026-09-03T05:22:33.839Z  tool_use  mcp__minidiscord-channel__reply

  방 DB 교차: id 115 🔒 05:21:09 → 116 ✅ 05:21:12 → … → 121 bot 05:22:33.
  jsonl 의 호출 시각과 방의 승인 요청 시각이 초 단위로 맞는다.

── ㉢ 답이 «이전 주제» 를 담았다 (조항의 Then) ──

  봇 답에 「마지막 테스트이길 바란다.」(note2.rtf 의 내용)와 note2.rtf 파일명이 있다.
  이 문자열은 `/clear` **이후** 방에 오간 말(id 114~120)에 **없다** — 레인 확인. 그러므로
  새 세션은 그것을 맥락이 아니라 `fetch_history` 로 되찾았다.

**증상.** 봇 답변이 「05:17(id 110): … 그 답을 보내기 전에 제 세션 맥락이 초기화돼 답이
나가지 못했습니다」라고 적었다. 그러나 방 DB 에는 **id 113(bot, 05:18:14)** 이 있다 —
그 답은 나갔다. 봇 진술이 세계와 어긋난다.

**조사 (레인이 새 세션 jsonl 의 `fetch_history` 결과를 직접 파싱).**

  결과 JSON: `cursor` = **110** · `messages` **54건** · id 목록 = **57 … 110** (연속)
  → **111·112·113·114 가 없다.** 113(봇 자신의 답)도, 114(사람의 이번 질문)도 없다.

  즉 **봇은 자기가 받은 것을 정확히 읽었다.** 창 안에 110 이 마지막이고 그 뒤에 봇 답이
  없으므로 「답이 나가지 못했다」는 그 창에서는 옳은 추론이다. 틀린 것은 세계에 대한
  결론이지 읽기가 아니다.

**원인 — 결함이 아니라 형제 SPEC 의 설계다.**

  `channel/src/index.ts` `fetchHistory` 의 2단계(REQ-BOTSTAB-007, **카드 t25**
  SPEC-BOTSTAB-001):
      while (총바이트 > MAX_HISTORY_BYTES) { 가장 **큰 id** 를 하나 버린다 }
      cursor = 남은 것의 id 최댓값
  `MAX_HISTORY_BYTES` = 16000 (`channel/src/truncate.ts:12`). 이번 창에는 🔒 승인 프레임이
  여럿 들어 있어 원소가 크고, 상한을 넘겨 **새것부터** 111~114 가 잘렸다.

  **버리는 방향이 «새것부터» 인 것은 의도다.** 그 파일의 주석이 근거를 적고 있다 —
  오래된 것부터 버리면 `cursor` 가 버려진 원소를 「이미 지나간 것」으로 선언해 그
  메시지들이 다음 요청부터 **영구히 사라진다**(SPEC-CHANINJECT-001 F-03 커서 오염).
  새것부터 버리면 버려진 것은 다음 요청에서 다시 온다. 그래서 이 동작은 **정상**이고,
  D-9 는 **결함이 아니다.**

**그러면 무엇이 남는가 — 관측 하나(수리 아님, 이 카드 범위 밖).**

  잘라낸 사실이 **소비자에게 보이지 않는다.** 결과 문서는 `{cursor, messages}` 뿐이고
  「몇 건을 버렸다」는 표시가 없다. 프로토콜을 아는 소비자는 `cursor` 를 다음 `since_id`
  로 넘겨 나머지를 받지만, **창을 완전한 것으로 읽은 소비자는 정확히 반대 결론에 이른다** —
  이번에 실제로 그렇게 됐다.

  이것은 이 프로젝트의 검증 규약이 이름 붙인 실패 부류와 같다: **「증거의 부재는 부재의
  증거가 아니다」.** 봇은 창 안에 없다는 것을 세계에 없다는 것으로 읽었다.

  처분: 고치려면 `SPEC-BOTSTAB-001` 의 결과 계약(문서 모양)을 바꿔야 하므로 이 카드의
  범위 밖이다. **관측으로만 등재**하고 처분은 리드·운영자 판단에 맡긴다.
  판정 무영향 — A08 이 재는 것은 「이전 주제를 답했는가」이고 그것은 성립했다.
