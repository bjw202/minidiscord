### 1.2 이 카드의 종결 정의

이 카드는 다음 셋이 서면 닫힌다.

1. 가짜 채널로 끝에서 끝까지 자동 검증된다.
2. 서버를 껐다 켜도 데이터가 남는 것이 매 실행 재확인된다.
3. **README 문구 갱신 — 트리거는 t6, 「내 PC」 문구는 t26 이월 · 과도기 공시.** 배포 경고 세 자리의 문언 교체와 보류 카드 트리거 세 줄 추가는 **이 카드(`t6`)가 한다**. 「내 PC에서만 도는 서버」라는 배치 전제 서술(README 3·190행)의 정정은 **카드 `t26` 으로 이월된다**(정본 배정 — §3 D5·§5). 따라서 **이 카드가 닫히는 시점의 README 에는 어긋남이 하나 남아 있다** — 트리거 ㉠ 은 «사내망 전용»을 말하는데 3·190행은 «내 PC»라 말한다. **그 과도기적 어긋남은 이 카드의 미결이 아니라 공시된 이월이며, `t26` 이 닫는다.**

> **3번 항목은 v0.3.0 에서 고쳤고, 문언 형태는 리드가 지정했다(2026-08-31).** v0.2.0 은 «README 가 실제 배치와 어긋나지 않는 상태»라고 적어 두었는데, 같은 판에서 D5 가 README 정정을 t26 으로 넘기면서 **그 문장이 거짓이 되었다**(2회차 감사 N-04) — 두 문장이 동시에 참일 수 없었다. 이 저장소가 반복해 기록한 「정정이 스스로 낡은 기록을 남긴다」의 재현이며, 이번에는 낡은 것이 **값이 아니라 명제**여서 값 어간 훑기에 걸리지 않았다. 그래서 §7.3 에 **명제 훑기**를 값 훑기와 나란히 세웠다.

- **REQ-E2E-001** — `scripts/` 아래의 E2E 스크립트는 실제 서버 프로세스 하나와 가짜 채널 클라이언트(평범한 WebSocket 클라이언트)만으로 시나리오를 구동한다. 이 스크립트는 Claude 세션을 띄우지 **않으며**, 어떤 외부 유료 API 도 호출하지 **않는다**. **[HARD] 이 무호출 성질은 주장이 아니라 기계 검사로 뒷받침한다** — 스크립트 원문에 Anthropic 계열 종단점·`claude` 실행 파일 spawn 이 등장하지 않아야 하고, 그 부재를 AC-E2E-016 이 금지어 검사로 잰다.
- **REQ-E2E-002** — 가짜 채널은 상호 인증 v2 의 4프레임 악수(`hello{pub, client_nonce}` → `challenge{server_nonce, room_id, bot_id, server_proof}` → `auth{signature}` → 봉투 `welcome`)로 접속한다. v1 형태 `hello{token}` 을 세션 확립 경로에 써서는 **안 된다**. 다만 **음성 대조군으로서** v1 형태를 보내는 별도 소켓 하나를 시나리오에 두어, 그것이 **어떤 프레임도 받지 못하고 닫히는지**를 관측한다.
- **REQ-E2E-003** — 세션 확립 이후 서버가 보내는 모든 프레임은 봉투(`{type:'env', seq, mac, payload}`)이므로, 스크립트는 봉투의 `mac` 과 `seq` 를 검증하고 푼 뒤에야 안쪽 프레임을 읽는다.
- **REQ-E2E-004** — **When** 시나리오의 어떤 단언이 거짓이면, 스크립트는 기동한 서버 프로세스와 임시 데이터 디렉터리를 정리한 뒤 0 이 아닌 종료 코드로 끝난다.
- **REQ-E2E-005** — 스크립트는 매 실행마다 새 임시 데이터 디렉터리를 쓰고, 개발자의 기본 데이터 경로(`./data`)를 읽지도 쓰지도 **않는다**.
- **REQ-E2E-006** — **When** 서버가 정해진 시한 안에 `/api/health` 에 응답하지 않으면, 스크립트는 무한히 기다리지 않고 **고정 표지 `[boot-timeout]` 를 표준출력에 찍은 뒤 전용 종료 코드 `9` 로** 끝난다. 이 경로를 밖에서 만들 수 있도록, 스크립트는 환경변수 `E2E_FORCE_PORT` 가 있으면 **그 포트를 그대로 서버에 넘긴다**(없으면 빈 포트를 스스로 잡는다) — 이미 점유된 포트를 주면 기동이 실패해 이 경로가 밟힌다.
- **REQ-E2E-007** — 시나리오는 다음 열다섯을 순서대로 덮는다: ① 가입·로그인 ② 방 생성 ③ 봇 등록 ④ 봇 초대(토큰 발급) ⑤ v2 접속과 봉투 `welcome` ⑥ **v1 `hello{token}` 음성 대조군 — 프레임 0건 수신 후 닫힘** ⑦ `@TO` 라우팅 수신 ⑧ 봇 답변 + 첨부 저장 ⑨ 첨부 내려받기 ⑩ 멘션 없는 메시지 저장 ⑪ `history_request` 전체 조회와 `since_id` 커서 조회 ⑫ 권한 릴레이(요청 → 방 `yes` → `permission_verdict` 수신) ⑬ 재접속 시 놓친 메시지 재전송 ⑭ **서버 재시작 후 영속성** ⑮ 방 보관 후 접속 거부. **[HARD] 각 단계의 진행 표지 `[n/15]` 는 그 단계의 단언이 모두 성공한 **뒤에** 찍는다** — 앞에서 찍으면 단언이 줄줄이 실패해도 표지 열이 온전해져 순서 증거가 거짓이 된다.

### 2.2 서버 재시작 영속성

- **REQ-E2E-008** — **When** 서버 프로세스를 종료하고 같은 데이터 디렉터리로 다시 띄우면, 재시작 이전의 대화·첨부 파일·봇 토큰이 남아 있어 조회와 재접속이 된다.
- **REQ-E2E-009** — 영속성은 E2E 스크립트 **밖에서도** 재는 인프로세스 회귀 짝을 갖는다 — `server/test/` 의 vitest 가 같은 데이터 디렉터리로 `buildServer()` 를 두 번 세워 관측한다. **[HARD] 두 번째 구축 전에 첫 연결을 명시적으로 닫는다**(`app.db.close()`) — Fastify 의 `close()` 는 `app.db` 를 닫지 않으므로, 닫지 않으면 「재시작」 이 아니라 「두 연결 병존」 을 재게 된다.
- **REQ-E2E-010** — 영속성 판정은 «재시작 전후 메시지 개수의 산술 비교» 가 **아니라**, 특정 메시지 id 의 본문·특정 첨부의 바이트·특정 토큰의 재접속 가능 여부라는 **동일성**으로 한다.

### 2.3 배선

## 3. 설계 결정 (리드 검토 대상)

### D1 — 악수 하네스를 재사용할 것인가, 셋째 사본을 쓸 것인가

- **(a) 재사용 [레인 잠정 선택]**: `scripts/e2e.mts` 로 쓰고 `npx tsx` 로 돌리며, `server/test/gateway-v2.ts` 의 `connectV2`·`innerOf` 를 **가져다 쓴다**.
- **(b) 셋째 사본**: 평범한 `.mjs` 로 쓰고 v2 악수를 스스로 다시 구현한다.

**(a) 를 고른 이유.** ① 단순성 사다리 — 이미 있는 헬퍼가 정확히 이 일을 한다. ② **독립성 축이 무너지지 않는다**: `gateway-v2.ts` 주석(1-5행)이 밝히듯 그 하네스의 독립성은 「사본이 여럿」이 아니라 「**구현 함수를 부르지 않고 스스로 유도한다**」에 있다. ③ 구현↔하네스 어긋남은 이미 왕복 기준 `AC-GWAUTH2-020` 이 소유한다 — 사본을 늘리면 감시자 없는 사본만 늘어난다.

**(a) 의 비용**: E2E 가 `server/test/` 를 가로질러 상대 경로로 import 한다. 스크립트 머리 주석으로 공시한다.

**[감사 D-01 에 대한 부분 반박 — `recordSocket` 은 쓰지 않는다.]** 1회차 감사는 AC-E2E-002 를 `gateway-v2.ts:100` 의 `recordSocket()` 으로 다시 쓰라고 처방했다. **발견(기준이 측정 불가라는 것)은 전건 수용하나, 그 기제는 채택할 수 없다** — 근거는 실측이다:

- `recordSocket(ws)` 은 **서버 쪽 `WebSocket` 객체를 감싼다**(`gateway-v2.ts:108-119` 가 그 객체의 `send` 를 교체한다). 그 객체는 `createGateway` 의 `onConnection` 콜백으로만 나온다 — `grep -n "onConnection" server/src/gateway.ts` → `85`(주석: «하네스가 서버 쪽 소켓을 관측하는 **유일한** 창구»)·`87`·`103`.
- **E2E 는 서버를 별도 프로세스로 띄운다**(REQ-E2E-001·plan §D-1). 다른 프로세스의 객체를 감쌀 방법은 없다 — 구조적으로 닿지 않는다.
- `buildServer()` 도 `onConnection` 을 넘기지 않는다 — `sed -n '47p' server/src/index.ts` → `const gateway = createGateway(app, { uploadsDir: config.uploadsDir, botFilesDir: config.botFilesDir })`. 인프로세스 짝이 `recordSocket` 을 쓰려면 `gateway.test.ts` 처럼 앱을 손으로 조립해야 하고, 그것은 재시작 짝이 필요로 하지 않는 조립을 하나 더 만든다.

**대신 같은 것을 전선에서 잰다**: ㉠ **양성** — `connectV2` 가 해소된다는 사실 자체가 v2 성립의 증거다(그 함수가 `server_proof` 를 상수 시간 대조하고 봉투를 검증한 뒤에만 해소한다 — `gateway-v2.ts:40-73`). ㉡ **음성 대조군** — 시나리오 안에서 별도 소켓 하나가 `{type:'hello', token}` 을 보내고, **프레임 0건 수신 후 닫힘**을 단언한다. 서버의 `dropConn` 이 아무것도 보내지 않고 닫으므로(`gateway.ts:118-122`) 이 관측은 실재한다. **공유 하네스를 편집하지 않으므로 감사가 지적한 「변이가 지나치게 굵다」 도 함께 해소된다.**

### D2 — `npm test` 편입 vs 별도 `npm run e2e`  **[잠정: 별도]**

① E2E 는 프로세스와 포트를 잡아 실패 양상이 단위 스위트와 다르다 — 섞이면 기준선이 흐려진다. ② `npm test` 는 워크스페이스 위임인데 E2E 는 루트에서 둘을 함께 구동한다. ③ **CI 배선은 카드 `t27`(N4) 소유**라 여기서 `npm test` 를 바꾸면 t27 의 자리를 미리 흔든다.

## 5. 범위 밖 (exclusions)

이 절은 **이 카드가 만들지 않는 것**을 적는다. 각 항목에는 소유 카드가 있다.

### Out of Scope — 첨부 파일 부재 시 500 (카드 `t8`)

- `server/src/routes-messages.ts:163` 의 `return reply.send(createReadStream(att.stored_path))` 는 앞선 경로 봉인 검사만 거치고 파일 존재를 확인하지 않는다 — 업로드 파일을 지우면 404 가 아니라 500 이 난다. 확인: `grep -c existsSync server/src/routes-messages.ts` → **0**. **가드도 시험도 이 카드에서 만들지 않는다.**

- E2E 시나리오의 첨부 내려받기 단계는 **존재하는 파일**만 내려받으므로 이 결함을 밟지 않는다.

### Out of Scope — 봇 동작 안정성 (카드 `t25` / N2)

- 재접속 순서 변이(F-11, `channel/src/gateway-client.ts` 의 `stopped` 가드)와 렌더 바이트 상한(F-09)은 이 카드가 다루지 않는다.

### Out of Scope — README «내 PC» 정정과 `config.ts` 주석 (카드 `t26` / N3)

- **정본이 둘을 한 묶음으로 N3 에 넣는다** — `proposal.md` §5 마지막 문장. 따라서 **README:3·190 의 배치 전제 서술도, `server/src/config.ts` 주석도 이 카드가 고치지 않는다**(REQ-E2E-013).

### Out of Scope — CI 테스트 배선 (카드 `t27` / N4)

- `.github/workflows/` 에 테스트 워크플로를 만들지 않는다. `npm run e2e` 를 CI 에 태우는 것도 t27 의 몫이다.
- 이 카드는 t27 이 부를 **명령 하나를 만들어 두는 데까지**다.

### Out of Scope — 서버 TLS 종단 (카드 `t23`)

- 중계형 중간자와 채널 바인딩은 이 카드가 닫지 않는다. E2E 는 평문 `ws://` 로 붙고 채널 바인딩은 `unbound` 다 — 그것이 지금의 사실이며, E2E 가 그 사실을 바꾸지 않는다.

### Out of Scope — 실 Claude 세션 수동 검증

- **어느 쪽이든 수행하지 않는다**(D3). README 에 체크리스트를 **싣는 경우**에는 「아직 수행되지 않았다」는 면책 문구를 같은 절에 함께 적고, 싣지 않기로 하면 그대로 둔다 — **게재를 의무화하는 요구사항은 없다**(REQ-E2E-016 후반절은 `Where` 조건형이고 AC-E2E-016 측정 ③은 「해당 없음」을 허용한다). v0.2.0 은 「싣되」라고 적어 **게재를 결정된 것처럼** 단정했다(2회차 감사 N-08).
- 게재 여부와 무관하게, 이 카드의 어떤 기준도 수동 검증의 수행을 주장하지 않으며 AC-E2E-016 의 측정 ①·②가 그 주장의 부재를 **금지어 검사**로 무조건 잰다.

### 7.3 정정 뒤 재훑기 — 값과 **명제**

v0.2.0 의 훑기는 옛 **값**만 열거해, D5 뒤집기가 거짓으로 만든 **문장**을 놓쳤다(2회차 감사 N-04). v0.3.0 은 두 축을 따로 훑는다.

**[HARD] 훑기 결과는 파일 전체의 원시 개수로 못박지 않는다.** 이 표 자신과 DoD 6·7항이 그 값들을 문자 그대로 담고 있어, **원시 개수는 이 표를 한 줄 고칠 때마다 흔들리고 표가 자기를 센다** — 2회차 감사 N-02 가 잡아낸 것과 같은 부류다(실제로 v0.3.0 작성 중 재현했다: `grep -rn ':173' .` 이 v0.2.0 의 `2` 에서 `4` 로 늘었고, 늘어난 둘이 이 표와 DoD 자신이었다).

- **명제 축**은 그 방식을 쓸 수 없다 — 명제는 산문에 살기 때문이다. 대신 **이 표의 자기 적중 줄에 `[SWEEP-ROW]` 표지를 달고 명령에서 `grep -v` 로 뺀다.** 표지는 파일에 남아 감사 가능하고, 제외가 명령 안에 있다.

> **이 표는 3회차 감사 P-01~P-03 을 닫으며 고쳤다.** v0.3.0 의 명제 축 두 행은 **원시 파일 개수를 그대로 못박아 표가 자기를 셌고**(행7 은 `3` 이라 적었으나 실측 `6` — 뒤 셋이 이 표 자신), 행7 의 판정 열은 셋째를 「3번 항목」이라 적었는데 그 줄에는 해당 문자열이 없었다(`sed -n '51p' spec.md | grep -c '종결'` → `0`). **바로 위 [HARD] 규칙을 이 표가 스스로 위반한 형태**다 — 값 축은 이미 그 처방을 썼는데 새로 더한 명제 축에는 적용하지 않았다. 값을 `6` 으로 고치는 것은 처방이 아니다(다음 편집에 또 어긋난다). **제외를 명령 안에 넣어 부류로 닫았다.**

### 7.4 재지 않은 것 (Gaps)

- **E2E 시나리오를 실제로 한 번도 돌려보지 않았다.** 이 SPEC 은 스크립트가 무엇을 해야 하는지를 정의할 뿐, 통과한다는 증거를 갖고 있지 않다.
- **서버 프로세스를 이 나무에서 띄워 보지 않았다.** `node_modules` 가 없어(측정 5) 기동은 부모 디렉터리 해소에 기대야 하고, 그 상태에서 잰 결과는 CI 를 대표하지 않는다. run 단계의 첫 일이 `npm install` 후의 기동 확인이다.
- **`npm test` 를 이 나무에서 돌리지 않았다.** 그래서 이 SPEC 은 어떤 통과 수치도 인용하지 않는다.
- **`connectV2` 가 별도 프로세스의 서버와 실제로 붙는지 실행 확인하지 않았다.** `scripts/e2e.mts` → `../server/test/gateway-v2.ts` 의 `tsx` 해소도 확인하지 않았다 — D1(a) 채택의 잔여 위험이며 plan §C 가 그것을 처음 잰다.
- **`openDb(':memory:')` 변이를 실행하지 않았다** — 신규 재시작 시험만 빨갛게 하는지 스위트 전반인지 모른다. DoD 가 변이표에 「빨개진 시험」 열을 요구해 run 단계에서 이 구분이 기록되게 했다(감사 D-15).
- **README 갱신 후 상태를 재지 않았다** — §7.2 의 「갱신 후 기대」 열은 예측이지 관측이 아니다.
- **`channel/src/gateway-client.ts` 를 읽지 않았다** — t25 경계의 타당성은 카드 기록에 기댔다.
- **`.github/workflows/` 를 이 나무에서 열지 않았다** — t27 경계는 정본 §7 의 실측 인용이다.
