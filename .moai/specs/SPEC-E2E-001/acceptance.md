# SPEC-E2E-001 — 수용 기준

> 기준은 전부 **명령의 종료 코드나 출력이 판정**한다. 각 기준에는 「사전 상태」(갱신·구현 **전** 실측값)와 「이 기준이 잡는 변이」를 함께 적는다.
>
> **사전 상태를 적는 이유**: 1회차 감사가 「사전 상태만으로 이미 충족되는 기준」 셋을 찾았다(D-03·D-04·D-08). 사전 상태가 본문에 있으면 그 형태가 다시 생기지 않는다.
>
> **[HARD] `git diff` 는 언제나 기준선과 함께 쓰고, 기준선은 셸 변수가 아니라 리터럴로 적는다** — 이유 둘. ① 인자 없는 `git diff` 는 워킹트리 대 인덱스라서 **커밋 뒤 항상 빈 출력**이고, 그 위에 세운 기준은 무조건 초록이다(1회차 감사 D-02). ② 기준선을 `"$BASE"` 같은 **변수로 적으면 그 변수가 비었을 때 `..HEAD` 가 `HEAD..HEAD` 로 해석되어 다시 무조건 초록**이 된다 — 실행 확인: `unset BASE; git diff --name-only "$BASE"..HEAD; echo "exit=$?"` → 빈 출력, `exit=0` (2회차 감사 N-01).
>
> 따라서 이 문서의 기준선은 **리터럴 `2a19d7d`**(이 워크트리의 분기점)이며, 명령 형태는 `git diff --name-only 2a19d7d..HEAD` 다. **`"$BASE"` 형태를 쓰는 실행 명령은 이 SPEC 에 0건이어야 한다** — 훑기 `grep -n '\$BASE' spec.md plan.md acceptance.md` 의 적중은 **정확히 2건**이고 **둘 다 이 규약 문단 자신**(바로 위 줄과 이 줄)이어야 한다. 실행 확인: 이 개정 시점에 적중 2건, 둘 다 이 문단. 세 번째 적중이 나오면 누군가 변수 형태를 되살린 것이다. (DoD 7항)
>
> 리터럴이라도 **기준선 커밋 자체가 사라질 수는 있으므로**(히스토리 재작성·얕은 클론), 기준선에 기대는 **모든** 기준은 생존 가드 `git rev-parse --verify 2a19d7d >/dev/null; echo "exit=$?"` → `exit=0` 을 함께 갖는다. 한 자리만 갖고 다른 자리가 없으면 그 자리가 조용히 샌다 — 2회차 감사 N-01 이 정확히 그 비대칭이었다(AC-E2E-011 에는 가드가 있고 AC-E2E-013 에는 없었다).
>
> 표기: 모든 명령은 워크트리 루트에서 실행하고, **`npm install` 이 선행**한다(spec.md §7.1 측정 5 — 이 나무에는 `node_modules` 가 없다).

## A. 기준 목록

### AC-E2E-001 — 정상 경로에서 E2E 가 통과한다

- **Given** `npm install` 이 끝난 저장소에서
- **When** `npm run e2e` 를 실행하면
- **Then** 종료 코드가 `0` 이고, 표준출력의 마지막 줄이 전체 통과를 알린다.
- 측정: `npm run e2e; echo "exit=$?"` → `exit=0`
- 사전 상태: `scripts/` 부재 → 이 명령 자체가 실행 불가(`npm run e2e` 는 스크립트 없음 오류).
- **잡는 변이**: 시나리오의 어느 경로든 깨지면 빨개진다. 단독으로는 「무엇이」 깨졌는지 못 가리므로 AC-E2E-002~008 이 갈래별로 잰다.

### AC-E2E-002 — 접속이 **전선에서** v2 로 성립하고, v1 은 거절된다

v0.1.0 은 `scripts/e2e.mts` 안의 `'hello'` **소스 문자열**을 grep 했다. D1(a) 를 고르면 그 문자열은 `server/test/gateway-v2.ts:35` 에 있고 스크립트에는 없으므로 **측정 대상이 존재하지 않았다**(감사 D-01, SPEC 내부 모순). 소스가 아니라 **동작**을 잰다.

- **Given** 발급받은 봇 토큰과 기동한 서버가 있을 때
- **When** ㉠ 가짜 채널이 `connectV2(port, token)` 로 붙고, ㉡ **별도 소켓 하나**가 v1 형태 `{type:'hello', token}` 을 보내면
- **Then** ㉠ 은 봉투 검증을 통과한 `welcome` 을 얻고, ㉡ 은 **어떤 프레임도 받지 못한 채 닫힌다**.
- 측정 ㉠(**양성**): `[5/15]` 표지가 찍힌다. `connectV2` 는 `server_proof` 를 상수 시간 대조하고 봉투 `mac`·`seq` 를 검증한 뒤에만 해소하므로(`gateway-v2.ts:40-73`), 이 표지는 **v2 악수가 실제로 성립했을 때만** 나온다.
- 측정 ㉡(**음성 대조군**): `[6/15]` 표지가 찍힌다. 단언은 「close 이벤트가 오기까지 수신 프레임 수 == 0」.
- 사전 상태: 두 표지 모두 없음(스크립트 부재).
- **잡는 변이**: ① `gateway.ts:156` 의 `pub`/`client_nonce` 형식 검사를 지우면 v1 소켓이 닫히지 않아 **㉡ 이 빨개진다**. ② `gateway.ts:191`(auth 서명 검증 `if (!ok) { dropConn(ws); return }`)을 지워도 ㉠ 은 여전히 통과하므로 ㉠ 은 그 층을 재지 않는다 — **재지 않는다는 사실을 여기 적어 둔다**(그 층은 `SPEC-GWAUTH-002` 의 기준이 소유한다).
- **공유 하네스를 편집하지 않는다**: 두 측정 모두 `scripts/e2e.mts` 안에서만 이뤄진다. v0.1.0 의 측정 ②는 `server/test/gateway-v2.ts` 편집을 요구했고, 그 파일은 서버 스위트 전체가 공유하므로 변이가 지나치게 굵었다(감사 D-01).

### AC-E2E-003 — 확립 이후 프레임을 봉투에서 풀어 읽는다

- **Given** `welcome` 이후의 서버 프레임이 전부 봉투일 때
- **When** 스크립트가 `message`·`history_response`·`permission_verdict` 를 읽으면
- **Then** 봉투 검증(`mac` 일치 + `seq` 단조 증가)을 거친 뒤에만 안쪽 프레임을 소비한다.
- 측정(**변이**): 봉투 해제 호출(`innerOf`)을 원문 `JSON.parse` 로 바꾸고 `npm run e2e` → **exit≠0**, 그리고 실패가 `[7/15]` 이후에서 난다.
- 사전 상태: 해당 없음(스크립트 부재).
- **잡는 변이**: 서버가 `sendEstablished` 대신 맨몸 `send` 로 보내도록 바꾸면(= 봉투 제거) 정상 경로가 빨개진다. 즉 스크립트의 문법이 아니라 **봉투가 실제로 씌워져 있음**을 잰다.

### AC-E2E-004 — 실패가 종료 코드로 전파되고 프로세스가 남지 않는다

- **Given** 시나리오 중간의 단언 하나를 거짓으로 바꾼 스크립트에서
- **When** `npm run e2e` 를 실행하면
- **Then** 종료 코드가 `0` 이 아니고, 실행이 끝난 뒤 기동했던 서버 프로세스가 남아 있지 않다.
- 측정: 변이 실행 → `echo "exit=$?"` 가 `0` 이 아님, 직후 `pgrep -f "tsx server/src/index.ts"; echo "pgrep=$?"` → `pgrep=1`(적중 없음).
- 사전 상태: 해당 없음.
- **잡는 변이**: 실패 경로의 `process.exit(1)` 을 `process.exit(0)` 으로 바꾸거나 정리 함수의 `kill()` 을 지우면 빨개진다. **이 기준이 없으면 AC-E2E-001 은 「무엇이든 exit 0」 인 스크립트에도 초록을 준다.**

### AC-E2E-005 — 개발자의 `./data` 를 건드리지 않는다

- **Given** 실행 전 `./data` 의 파일 목록과 내용 해시를 기록한 상태에서
- **When** `npm run e2e` 를 한 번 완주하면
- **Then** 목록과 해시가 실행 전과 같다.
- 측정: 실행 전후로 `find data -type f 2>/dev/null | sort | xargs -r shasum -a 256 | shasum -a 256` 를 돌려 두 출력을 비교 → 동일. (`./data` 가 없으면 양쪽 모두 빈 입력의 해시로 같다.)
- 사전 상태: `which shasum` → `/usr/bin/shasum` (macOS 기본이라 새 러너에서도 있다). v0.1.0 은 `sha256sum` 과 `ls -laR` 를 썼는데, 전자는 macOS 기본이 아니라 **부재 시 양쪽이 똑같은 오류 문자열이 되어 「동일」로 초록**이 될 수 있었고 후자는 시각을 섞었다(감사 D-11).
- **잡는 변이**: 스크립트에서 `MINIDISCORD_DATA_DIR` 지정을 지우면 서버가 기본 `./data` 를 만들어 쓰므로 빨개진다.

### AC-E2E-006 — 기동 시한 초과가 **양성 표지와 전용 종료 코드**로 드러난다

v0.1.0 은 `exit != 124` 라는 **부정 단언**이라 무슨 이유로든 일찍 죽으면 초록이었다 — 특히 「의존성 부재 안내」 경로(exit 1)만 밟아도, 시한 폴링 코드가 한 줄도 실행되지 않은 채 통과했다(감사 D-06).

- **Given** `E2E_FORCE_PORT` 에 **이미 점유된 포트**를 넣어 기동을 실패시키면 (REQ-E2E-006 이 이 주입 기제를 요구한다)
- **When** `npm run e2e` 를 실행하면
- **Then** 표준출력에 `[boot-timeout]` 이 정확히 한 번 찍히고, 종료 코드가 **정확히 `9`** 다.
- 측정:
  ```
  # 점유자를 실제로 세운다 — 산문이 아니라 실행 가능한 형태여야 한다 (2회차 감사 N-05)
  node -e 'const s=require("net").createServer().listen(0,"127.0.0.1",()=>{console.log(s.address().port);setInterval(()=>{},1e9)})' > /tmp/t6-port.txt &
  HOLDER=$!; sleep 1; PORT=$(cat /tmp/t6-port.txt)
  E2E_FORCE_PORT=$PORT npm run e2e > /tmp/t6-boot.log 2>&1; echo "exit=$?"
  grep -c '\[boot-timeout\]' /tmp/t6-boot.log
  kill $HOLDER
  ```
  → `exit=9` **그리고** `1`.
  - v0.2.0 은 `# 점유자 확보 후` 라는 **산문**만 두고 `$PORT` 를 묶는 명령이 없었다(2회차 감사 N-05). 빈 값이면 `E2E_FORCE_PORT=` 가 되어 스크립트가 빈 포트를 스스로 잡고 정상 기동해 `exit 0 ≠ 9` 로 **빨개지므로 「초록으로 새는」 방향은 아니었으나**, Given 을 만들 수 없어 기준을 돌릴 수 없었다.
  - **점유자는 `kill` 로 반드시 거둔다.** 배경 프로세스를 남기는 검증 절차는 그 자체가 위험이다.
  - **[공시된 잔여 위험 — run M1 에서 실측·보완한다 (3회차 감사 P-06, 리드 결정으로 이월)]** 이 블록은 **한 번도 돌려보지 않았다**. 알려진 취약점 둘:
    - **`sleep 1` 은 경주다.** node 기동이 느리면 `$PORT` 가 비어 `E2E_FORCE_PORT=` 가 되고, 스크립트가 빈 포트를 스스로 잡아 정상 기동한다. **방향은 안전하다** — `exit 0 ≠ 9` 라서 초록으로 새지 않고 빨개진다. 그래도 그때 빨간 이유는 「시한 폴링이 없어서」가 아니라 「Given 을 못 만들어서」이므로, run M1 에서 **고정 대기 대신 준비 신호 대기**(포트가 실제로 잡힐 때까지 폴링)로 바꾼다.
    - **`/tmp/t6-port.txt` 는 OS 가 비우는 자리다.** 이 저장소 규약은 검증 증거를 `.moai/state/verify/` 에 남기라 한다 — run M1 에서 경로를 옮긴다.
    - **지금 고치지 않는 이유**: 둘 다 실행해 봐야 형태가 정해지는데 이 나무에는 `node_modules` 가 없어 돌릴 수 없다. **추정으로 고쳐 쓰면 재지 않은 값을 적는 것이 된다.**
- 사전 상태: `E2E_FORCE_PORT` 도 `[boot-timeout]` 도 **구현 대상에 없다** — `grep -rn "E2E_FORCE_PORT\|boot-timeout" README.md package.json server channel | wc -l` → **`0`**.
  - **제외를 괄호가 아니라 명령 안에 넣었다.** v0.3.0 은 대상을 `.`(나무 전체)로 적고 「이 SPEC 문서 제외」를 산문으로 덧붙였는데, 적힌 그대로 돌리면 `25` 가 나온다 — SPEC·감사·개정 보고서가 이 문자열을 정당하게 담고 있기 때문이다(3회차 감사 P-05). **인용한 명령이 인용한 값을 내야 한다.**
- **잡는 변이**: 시한 폴링을 지워 무한 대기로 되돌리면 표지가 찍히지 않아 두 측정 모두 빨개진다. 다른 이유로 죽는 경우(의존성 부재 등)는 exit 이 `9` 가 아니므로 **초록으로 새지 않는다**.

### AC-E2E-007 — 열다섯 단계를 **성공한 순서대로** 덮는다

- **Given** 각 단계의 단언이 **성공한 뒤에** `[n/15]` 표지를 찍는 스크립트에서 (REQ-E2E-007 [HARD])
- **When** `npm run e2e` 를 완주하면
- **Then** 열다섯 표지가 전부, 명시된 순서대로 나오고, **파이프라인 종료 코드도 0** 이다.
- 측정:
  ```
  set -o pipefail
  npm run e2e > /tmp/t6-e2e.log; echo "exit=$?"
  grep -o '^\[[0-9]\+/15\]' /tmp/t6-e2e.log | tr -d '\n'
  ```
  → `exit=0` **그리고** `[1/15][2/15]…[15/15]` 와 정확히 일치.
- 사전 상태: 해당 없음.
- **잡는 변이**: ① 한 단계를 지우면 문자열이 어긋난다. ② 단계 순서를 바꿔도 어긋난다(개수가 아니라 순서 문자열 전체를 대조한다). ③ **표지를 단언 앞에서 찍도록 바꾸면** 단언이 실패해도 표지 열이 온전해지는데, 그때는 `exit` 이 0 이 아니어서 잡힌다 — v0.1.0 은 출력을 파이프로 넘겨 `tr` 의 종료 코드를 읽었기에 이 실패를 버렸다(감사 D-10).

### AC-E2E-008 — 실프로세스 재시작 뒤 세 가지가 그대로다

- **Given** 재시작 전에 기록해 둔 「메시지 id 와 그 본문」, 「첨부 id 와 그 바이트의 해시」, 「봇 초대 토큰」 이 있을 때
- **When** 서버 프로세스를 종료하고 같은 데이터 디렉터리로 다시 띄우면
- **Then** ① 같은 id 의 메시지 본문이 글자 그대로 같고 ② 같은 첨부 id 를 내려받은 바이트의 해시가 같고 ③ 같은 토큰으로 v2 재접속해 봉투 `welcome` 이 온다.
- 측정: 세 단언이 `[14/15]` 단계 안에서 실행되고, 하나라도 어긋나면 exit≠0.
- 사전 상태: 해당 없음.
- **잡는 변이**: `openDb(config.dbPath)` → `openDb(':memory:')` 로 바꾸면 ①③이 빨개지고, 업로드 저장 경로를 임시 디렉터리로 바꾸면 ②가 빨개진다.
- **개수를 세지 않는다**: `messages.length` 비교를 쓰지 않는다 — spec.md §4 가 초안의 그 형태를 기각했다.

### AC-E2E-009 — 영속성에 **동작을 단언하는** 인프로세스 회귀 짝이 있다

v0.1.0 은 `npm test -w server | grep -c "restart"` 였다 — **시험 제목에 그 글자만 있으면 충족**되어, 아무것도 단언하지 않는 `it('restart persistence', () => {})` 가 통과했다(감사 D-08).

- **Given** `server/test/restart-persistence.test.ts` 가 있을 때
- **When** `npm test -w server` 를 실행하면
- **Then** 그 파일의 시험이 통과하고, 그 안에 **세 개의 동일성 단언**(메시지 본문 · 첨부 바이트 · 토큰 재접속)이 있으며, 두 번째 `buildServer()` 앞에 `app.db.close()` 가 있다.

- **잡는 변이 — [HARD] 이 변이는 DoD 2항의 필수 1건이다**: `server/src/index.ts:37` 의 `openDb(config.dbPath)` 를 `openDb(':memory:')` 로 바꾸면 **이 시험이 빨개져야 한다**. 변이표에 **「빨개진 시험 목록」** 열을 적어, 이 변이가 신규 시험만 잡는지 스위트 전반을 잡는지 구분한다(감사 D-15 — 후자라면 굵은 변이라 이 기준의 존재 이유를 증명하지 못한다).
- **왜 짝이 필요한가**: AC-E2E-008 은 셸이 판정하므로 스크립트 파일을 지우면 함께 사라진다. 이 시험은 `npm test` 안에 남아 **영속성을 지우는 변경을 회귀 스위트가 잡는다.**

### AC-E2E-011 — 배선이 기존 `test` 를 건드리지 않는다

- **Given** 기준선 리터럴 `2a19d7d` 에 대해

### AC-E2E-012 — 배포 경고가 **세 자리 각각에서** 문언만 바뀌었다

v0.1.0 의 세 측정은 전부 **파일 전역 개수**여서 「세 자리 각각」을 재지 못했고, 특히 측정 ③(`grep -c "배포 경계"` ≥ 1)은 **사전 상태가 이미 1** 이라 5행과 225행을 통째로 지워도 초록이었다(감사 D-04). 자리별 앵커로 다시 쓴다.

세 자리는 각각 고유한 앵커 토큰을 갖는다 — 사전 상태에서 셋 다 **정확히 1회**만 나타난다(spec.md §7.2).

- **Given** 갱신 전 세 자리(README 5·225·236행)가 각각 「생산 배치」를 담고 있을 때
- **When** 갱신 후 자리별로 재면
- **Then** 세 자리 **각각**에서 경고 문장이 살아 있고 문언이 「서비스화」로 바뀌었다.
- 측정 ①(어간 소멸): `grep -c "생산 배치" README.md` → `0`  *(사전 상태 **3**)*
- 측정 ②㉠(자리 A, README:5): `grep -c "지금 상태.*서비스화" README.md` → `1`  *(사전 상태 **0**)*
- 측정 ②㉡(자리 B, README:225): `grep -c "열린 갈래.*서비스화" README.md` → `1`  *(사전 상태 **0**)*
- 측정 ②㉢(자리 C, README:236): `grep -c "배포 경계.*서비스화" README.md` → `1`  *(사전 상태 **0**)*
- **잡는 변이**: ① 5행만 고치고 225·236 을 두면 측정 ①이 `2` 로 빨개지고 ②㉡㉢ 도 `0` 으로 빨개진다. ② 세 문장을 **통째로 지우면** 측정 ①은 `0` 이 되어 초록이지만 ②㉠㉡㉢ 이 전부 `0` 으로 빨개진다 — **v0.1.0 이 잡지 못하던 실패다.** ③ 어느 한 자리만 지워도 그 자리의 측정 하나가 빨개진다.
- 각 측정이 「앵커 **그리고** 새 문언」을 같은 줄에서 요구하므로, 문장이 그 자리에 남아 있으면서 바뀌었을 때만 초록이다.

### AC-E2E-013 — t26 의 자리를 건드리지 않았다 (울타리)

정본(`proposal.md` §5 마지막 문장)이 README 의 「내 PC」 정정과 `config.ts:5` 주석을 **한 묶음으로 N3(t26)** 에 넣는다. 따라서 이 기준은 **부재**를 잰다(spec.md §3 D5).

- **Given** 기준선 리터럴 `2a19d7d` 에 대해
- **When** 이 카드의 커밋들을 비교하면
- **Then** ① `server/src/config.ts` 가 변경 파일 목록에 없고 ② README 의 「내 PC」 두 자리가 기준선과 같다.
- 측정 ①: `git diff --name-only 2a19d7d..HEAD | grep -c "server/src/config.ts"` → `0`
- 측정 ②: `grep -c "내 PC" README.md` → **`2`** *(사전 상태 **2** — 3·190행. 값이 유지되어야 한다)*
- 측정 ③: `git diff 2a19d7d..HEAD -- README.md | grep -c "내 PC"` → `0` (그 두 줄이 diff 에 등장하지 않는다 — 추가로도, 삭제로도)
- 측정 ④(**기준선 생존 가드** — AC-E2E-011 측정 ③과 같은 것): `git rev-parse --verify 2a19d7d >/dev/null; echo "exit=$?"` → `exit=0`. **이 가드가 v0.2.0 에 없어서 이 울타리가 샜다**(2회차 감사 N-01) — 기준선이 해소되지 않으면 측정 ①·③이 빈 출력으로 조용히 초록이 되기 때문이다. 이제 기준선에 기대는 **두 기준 모두** 가드를 갖는다.
- **잡는 변이**: `config.ts:4` 주석을 함께 고치면 측정 ①이 `1` 로 빨개진다. README 3행이나 190행을 고치면 측정 ③이 `1` 이상으로 빨개진다(측정 ②만으로는 「고쳐 쓰되 같은 글자를 남김」을 못 잡으므로 ③을 함께 둔다).
- v0.1.0 은 기준선 없는 `git diff --name-only` 라 **커밋 뒤 무조건 초록**이었고, 그래서 이 울타리가 실제로는 서 있지 않았다(감사 D-02·§6 8행).

### AC-E2E-016 — 「수동 검증을 했다」·「유료 API 를 부른다」는 **글자가 없다**

v0.1.0 의 측정 ①은 「run 단계 자기 훑기로 확인한다」였다 — 돌릴 명령도 비교할 출력도 없는 **자기 신고**였고, 이 문서 머리말의 선언을 스스로 위반했다(감사 D-05). 실행 가능한 부재 검사로 바꾸고, REQ-E2E-001 후반절(유료 API 무호출)을 재는 자리도 여기에 흡수한다(감사 D-16 — 새 기준을 만들지 않는다).

- **Given** 이 카드가 실 Claude 세션을 띄우지 않는다는 결정(spec.md §3 D3)과 REQ-E2E-001 의 무호출 선언에서
- **When** 산출물 전체를 금지어로 훑으면
- **Then** ① 수동 검증 수행[AC-016-EXEMPT] 주장이 0건 ② Anthropic 계열 종단점·`claude` spawn 이 0건 ③ (체크리스트를 실은 경우) 면책 문구가 **그 절 안에** 있다.
- 측정 ①(수행 주장 부재 — **무조건**):
  ```
  grep -rEn "수동 검증(을)? ?(수행|완료)|실 세션으로 (확인|검증)|사람이 (직접 )?확인했" \
    README.md scripts/ .moai/specs/SPEC-E2E-001/ | grep -v 'AC-016-EXEMPT'; echo "exit=$?"
  ```
  → `exit=1`(적중 없음). **실행 확인: 이 개정 시점에 `exit=1`.**
- 측정 ①-b(면제가 조용히 불어나지 않음 — **면제된 «주장»의 수를 센다**):
  ```
  grep -rE "수동 검증(을)? ?(수행|완료)|실 세션으로 (확인|검증)|사람이 (직접 )?확인했" \
    README.md scripts/ .moai/specs/SPEC-E2E-001/ | grep -c 'AC-016-EXEMPT'
  ```
  → **`7` 이하**. 파일별로는 `spec.md` **3** · `plan.md` **1** · `acceptance.md` **3**. **실행 확인: v0.3.0·v0.3.1 인도 시점 모두 `7`** (합계와 파일별을 따로 쟀다).
  - **판정은 등가가 아니라 상한이다** — `7` **초과**면 누군가 새 주장을 면제로 덮은 것이므로 조사한다. **미만은 빨강이 아니다**: 아래 「불변의 범위」가 밝히듯 SPEC 자신의 인용 문장을 줄이면 값이 정당하게 내려가는데, 등가로 판정하면 그것이 허위 경보가 된다(3회차 감사 P-04).
  - **v0.2.0 의 형태(`grep -rc 'AC-016-EXEMPT' <파일들>`)는 폐기했다.** 그 형태는 **표지의 출현**을 세므로 이 기준 자신의 명령문(측정 ①의 필터, 측정 ①-b 의 `grep` 인자)까지 세어 **인도 시점에 이미 값이 어긋났다**(못박은 6 대 실측 8 — 2회차 감사 N-02). 새 형태는 **금지어 패턴에 걸리는 줄 중 면제된 것**만 세므로, 표지를 명령문에 아무리 써도 그 줄에 금지어 주장이 없으면 세지 않는다. **기준이 자기 문장을 세지 않으므로 이 문장을 고쳐도 값이 흔들리지 않는다** — 값을 다시 못박는 대신 **세는 대상을 바꿔** 부류를 닫았다.
  - **왜 면제가 필요한가**: 금지어를 **정의하는 문장**(REQ-E2E-016·§3 D3·이 기준 본문)은 금지어를 포함할 수밖에 없다. 필터 없이는 **기준이 자기 정의문에 걸려 영구히 빨갛다** — 개정 1차 중 실행으로 재현했다(적중 6건, 전부 자기 문서).
  - **불변의 범위 — 명령문에는 불변, 산문 인용에는 불변이 아니다.** v0.3.0 은 「이 문장을 고쳐도 값이 흔들리지 않는다」고 적었는데 **그 주장은 넓었다**(3회차 감사 P-04). 정확히는 이렇다:
    - **자기 명령문은 세지 않는다** — v0.2.0 이 「표지의 출현」을 세던 형태와 달리, 이제는 「금지어에 걸리는 줄 중 면제된 것」만 세므로 필터·`grep` 인자에 표지를 아무리 써도 값이 움직이지 않는다. 실행 확인: 못박은 숫자를 고친 뒤 재실행해도 `7` 이었다.
    - **자기 산문 인용은 센다** — 실측 7건은 **전부 SPEC 자신의 인용**이고 그중 셋이 이 기준 본문이다. 그 문장들의 금지어 표현을 바꾸면 값이 정당하게 내려간다. **그래서 판정을 등가가 아닌 상한(`7` 이하)으로 적었다** — 등가였다면 그 편집이 허위 경보를 낸다.
    - 값이 상한을 **넘으면** 새 주장이 면제로 덮인 것이므로 그 줄을 읽고 정당한 인용인지 판정한다.
- 측정 ①-c(**면제 표지의 우회 통로 차단**): `grep -rc 'AC-016-EXEMPT' README.md scripts/ 2>/dev/null` 의 합이 **`0`**. *(사전 상태: `grep -rc 'AC-016-EXEMPT' README.md` → **`README.md:0`**; `scripts/` 는 아직 없다)*
  - **왜 필요한가**: 측정 ①은 `README.md` 와 `scripts/` 에도 면제 필터를 걸지만, v0.2.0 의 ①-b 는 SPEC 3파일만 셌다. 그래서 「실 세션으로 확인했습니다 `[AC-016-EXEMPT]`」 한 줄을 **README 나 `scripts/` 에 넣으면 양쪽을 모두 통과**했다(2회차 감사 N-03). 하필 그 둘이 주장이 실제로 오독을 낳는 표면이다.
  - 규약(「README 와 `scripts/` 에는 면제 표지를 쓰지 않는다」)이 v0.2.0 에서는 **산문으로만** 있었다 — 강제하는 측정이 없는 규칙은 D-02 의 울타리와 같은 형태다. 이 측정이 그 규약을 산문에서 **측정으로 내린다**.
- 측정 ②(유료 API 무호출 — **무조건**):
  ```
  grep -rEn "anthropic|claude\.ai|api\.anthropic|spawn\(['\"]claude" scripts/ ; echo "exit=$?"
  ```
  → `exit=1`(적중 없음). *(사전 상태: `grep -rEn "anthropic|claude\.ai" README.md | wc -l` → **0**; `scripts/` 는 아직 없다)*
- 측정 ③(면책 문구 — **조건부**, 체크리스트를 실은 경우에만):
  ```
  awk '/수동 체크리스트/,/^## /' README.md | grep -cE "수행하지 않았|실행하지 않았"
  ```
  → `≥1`. 체크리스트를 싣지 않기로 하면 이 측정은 「해당 없음」으로 명시하되, **①②는 그대로 돈다** — 금지는 무조건이므로 이 기준이 기계적 증거 0건으로 소화될 수 없다(감사 D-12).
- **잡는 변이**: 「실 세션으로 확인했습니다」[AC-016-EXEMPT] 한 줄을 README 나 이 문서에 넣으면 측정 ①이 적중을 내어 빨개진다. E2E 가 `claude` 를 spawn 하도록 바꾸면 측정 ②가 빨개진다.

## C. 완료 정의 (DoD)

1. AC-E2E-001~016 전건 통과, 각 기준의 측정 명령과 **관측한 출력**이 `progress.md` §E.2 에 있다.
2. **변이표**: 위 기준들이 명명한 변이 가운데 **최소 8건을 실제로 실행**한다. 표의 열은 「지운 것 / 실행 명령 / **빨개진 시험·기준 목록** / 예상과 일치?」 넷이다.
   - **[HARD] 필수 1건**: AC-E2E-009 의 `openDb(config.dbPath)` → `openDb(':memory:')` 변이는 8건 안에 **반드시** 포함한다. 그 행의 「빨개진 시험 목록」이 신규 재시작 시험만인지 스위트 전반인지를 적는다 — 후자라면 굵은 변이라 AC-E2E-009 의 존재 이유가 증명되지 않으므로, 그 사실을 기록하고 기준을 좁힌다(감사 D-08·D-15).
   - **살아남은 변이(코드를 지웠는데 전부 초록)가 있으면 그 행을 그대로 남기고 기준을 고친다** — 표에서 지우지 않는다.
3. `npm test` 가 통과한다(서버 + 채널). 이 카드가 기존 시험을 하나도 빨갛게 만들지 않았음을 실행으로 확인한다.
4. **기준선 있는** diff 로 범위 밖 파일 부재를 확인한다: `git diff --name-only 2a19d7d..HEAD` 의 출력이 `scripts/e2e.mts` · `server/test/restart-persistence.test.ts` · `package.json` · `README.md` · `.moai/**` 안에 든다. 특히 `server/src/**` 가 **0건**이어야 한다(이 카드는 서버 코드를 고치지 않는다).
5. 어떤 숫자도 재지 않고 쓰지 않았다: 이 카드가 새로 적는 모든 수치는 실행한 명령과 함께 적히거나, 재지 않았으면 **지운다**. 정본 §2 의 README `303줄` 같은 **다른 나무의 값을 승계하지 않는다**.
6. **정정 뒤 재훑기 — 값과 명제를 모두 훑는다**: 이 카드가 고친 수치·줄 인용에 대해 **값 어간**을 훑고, 뒤집은 **결정·명제**에 대해 그 명제의 옛 형태와 부정형을 훑는다. 적중을 분류표로 남긴다(0건이면 0건이라고 적는다).
   - **[HARD] 명제 훑기를 값 훑기와 따로 세운다.** v0.2.0 의 훑기는 옛 **값**(`13`·`:173`·`sha256sum`·`124`)만 열거해, D5 뒤집기가 거짓으로 만든 **문장**(§1.2 종결 정의)을 놓쳤다 — 값이 아니라 명제였기 때문이다(2회차 감사 N-04). 결정을 뒤집을 때마다 「그 결정을 전제로 쓴 문장이 어디에 있나」를 어간으로 훑는다.
7. **기준선 표기 자기 검사** — `grep '^- 측정' acceptance.md | grep -c 'BASE'` → **`0`**. 실행되는 측정 줄에 기준선 변수 형태가 되살아나지 않았음을 잰다(2회차 감사 N-01).
   - **파일 전체 개수로 못박지 않는 이유**: 이 DoD 항목과 §7.3 훑기 표가 `$BASE` 라는 글자를 담고 있어 원시 개수는 산문을 고칠 때마다 흔들린다 — 못박으면 그것이 다시 「기준이 자기를 센다」(N-02)가 된다. **측정 줄로 범위를 좁히면 산문 편집에 불변**이다.
