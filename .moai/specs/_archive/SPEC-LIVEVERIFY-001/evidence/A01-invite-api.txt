A01 증거 2 (대체 매체) — 초대 발급 응답 기록
카드 t32 / SPEC-LIVEVERIFY-001 · 작성 2026-09-03 (run 레인)

이 파일은 무엇인가
  `acceptance.md` AC-001 증거 2 가 요구하는 «발급 측의 토큰 앞 8글자» 를 담는다. 작성 시점
  조항은 매체를 «웹 화면의 초대 대화상자 한 장»(A01-invite.png)으로 지정했으나, §19 의
  운영 인수로 초대가 API 로 이뤄지면서 그 가정이 소멸했다. 운영자 결정 (나) 로 인정 매체가
  «대화상자 캡처 또는 발급 응답 기록» 으로 확장됐고, 이 파일이 후자다.
  [HARD] 토큰 전문은 이 파일에도, 어느 증거에도 남기지 않는다 — 앞 8글자만 적는다.

── (A) 리드 관측 — 레인이 직접 실행하지 않았다 ──
  귀속: lead 세션, 2026-09-03 11:25 KST

    요청 : POST /api/rooms/1/invites      body {"bot_id": 1}
    인증 : jw-9(user 23) 의 md_session 쿠키
    응답 : 201
             bot_id    = 1
             bot_name  = "bot-01"
             token     = 42694b06…      ← 앞 8글자만 기록. 전문 금지
             command   = (생략 — 토큰 전문을 담으므로 기록하지 않는다)

  이 네 줄은 레인이 재현하지 않았다. 재현하려면 초대를 한 번 더 발급해야 하고 그것은
  #5 를 폐기시키므로(아래 (B) 참조), 재현 자체가 증거를 파괴한다. 그래서 귀속을 갈라 적는다.

── (B) 레인 직접 실측 — bot_tokens 상태 ──
  명령: sqlite3 <wt>/server/data/minidiscord.db
        "SELECT id, bot_id, room_id, created_at, revoked_at FROM bot_tokens ORDER BY id;"
  출력:
    id  bot_id  room_id  created_at           revoked_at
    1   1       1        2026-09-02 14:48:20  2026-09-03 00:01:14
    2   1       1        2026-09-03 00:01:14  2026-09-03 01:48:22
    3   1       1        2026-09-03 01:48:22  2026-09-03 01:50:40
    4   1       1        2026-09-03 01:50:40  2026-09-03 02:25:06
    5   1       1        2026-09-03 02:25:06  (NULL)             ← 유일한 유효 토큰

  #5 의 created_at 이 #4 의 revoked_at 과 같다 — 발급이 직전 토큰을 폐기한다는 것이
  데이터로 읽힌다. 리드 보고(«#4 revoked 02:25:06»)와 일치한다.

── (C) 왜 8글자를 서버에서 되찾을 수 없는가 (레인 직접 실측) ──
  bot_tokens 스키마에는 평문 토큰 열이 없다:
      verifier_pub TEXT UNIQUE NOT NULL   -- Ed25519 공개키 64자 hex
      server_confirm_key TEXT NOT NULL
  그리고 라우트가 갈린다:
      server/src/routes-bots.ts:91  POST …/invites → 201 { bot_id, bot_name, token, command }
      server/src/routes-bots.ts:99  GET  …/invites → SELECT t.bot_id, b.name …   ← token 없음
  즉 평문은 **발급 응답에만** 존재하고 그 뒤로는 어디에서도 되찾을 수 없다. 이것이
  「#5 의 대화상자를 나중에 다시 캡처한다」가 불가능한 이유이자, 이 파일이 (A) 의 값을
  리드 관측으로 받아 적을 수밖에 없는 이유다.

── (D) 인접하지만 ㉢ 의 증거가 아닌 것 — 혼동 방지 ──
  레인이 `ps eww -p 38988`(봇 claude 세션)에서 `MINIDISCORD_TOKEN=42694b06…` 를 읽었다.
  값은 (A) 와 앞 8글자가 일치한다. 그러나 이것을 **발급 측 증거로 쓰면 안 된다** —
  38988 은 ㉢ 비교의 **터미널 쪽**이고, 같은 쪽 값 둘을 맞대는 것은 비교가 아니다.
  ㉢ 은 「발급 측((A)) == 터미널 측(㉢ 의 echo 출력)」이어야 성립한다. 이 항목은 그
  경계를 흐리지 않기 위해 «증거 아님» 으로 명시해 둔다.

── 미검증 / 잔여 ──
  · (A) 는 레인 재현 없음(재현이 증거를 파괴하므로). (B)(C)(D) 는 레인 직접 실측이다.
  · 이 파일은 ㉢ 의 **한쪽**만 담는다. 나머지 한쪽인 터미널의
    `echo "${MINIDISCORD_TOKEN:0:8}"` 출력은 A01-session-terminal.png 가 담아야 하며,
    두 값이 같아야 ㉢ 이 선다. 이 파일 단독으로는 ㉢ 이 서지 않는다.
