## 1. 이 SPEC 이 고치는 것과 고치지 않는 것

**[HARD] 이 카드는 「게이트가 검사 없이 통과를 준다」를 고치지 않는다.**

고치는 것은 **이 저장소가 게이트에 건네는 검사 목록**이다. 종료 코드의 설계 — 「통과」와 「검사할 것을 못 찾음」을 같은 `0` 으로 내는 것 — 은 외부 바이너리(`~/.local/bin/moai`, 소스가 이 기계에 없다)의 소관이고 이 저장소 안에서 고칠 수 없다. 그 합류는 게이트 자신이 문서에 적고 있다:

> `moai gate --help`: **"Exit code 0: gate passed (or no recognized language toolchain detected)."**

그 결함은 카드 **t41** 로 분리되어 있다. 이 SPEC 은 t41 을 위한 수리를 설계하지 않는다.

## 2. 배경 — 실측된 세 가지 모양

카드는 조용한 초록을 두 갈래(㉮ 검사가 돌았는데 통과 · ㉯ 돌 것을 못 찾아 통과)로 가르라고 했다. **실측은 이 두 갈래를 반증했다.** 세 사례는 이렇게 갈린다:

| 사례 | 모양 | 실측 |
|---|---|---|
| ① zsh 조용한 0 | ㉯ 계열 — 셸이 파일 목록을 이름 하나로 넘겨 훑기가 **아무것도 못 찾고** 0 | zsh 0 / bash 74 / xargs 74 |
| ② 툴체인 미발견 | ㉯ — 게이트가 프로젝트를 못 찾아 **아무 단계도 돌지 않고** 0 | `cd .moai && moai gate` → RC=0 · stdout 0바이트 · 0.029초 |
| ③ 타입 오류 생존 | **㉰ — 두 갈래 어디에도 없다** | `npm run typecheck -w server` RC=1 인데 `moai gate` RC=0 · 0바이트 · 81초 |

**㉰ 「그 검사는 게이트의 목록에 없다」.** 게이트는 자기 단계 목록을 **전부 돌았고 정직하게 통과**했다. 타입 검사가 애초에 그 목록에 없었을 뿐이다. 이것은 게이트의 결함이 아니라 **이 저장소가 건넨 목록의 결함**이고, 그래서 이 저장소 안에서 고칠 수 있는 유일한 항목이다.

### 게이트가 이 저장소에서 실제로 도는 것 (문서 주장이 아니라 실측)

게이트 자신의 실패 출력(`.moai/reports/t40/evidence/gate-failtest.err`, 2081바이트)에 축자로 찍힌다:

```
quality gate failed: npm test
> npm test --workspaces --if-present --passWithNoTests
```

**단계는 이 하나뿐이다.** `channel` 은 자기 `pretest: tsc` 를 갖고 있어 타입 검사가 `npm test` 안에 딸려 온다. `server` 에는 `pretest` 가 없다 — 그래서 server 의 타입 오류는 게이트에 보이지 않는다.

### 공통 배경 — 통과는 침묵이다

정상 통과는 **RC=0 · stdout 0바이트 · stderr 0바이트 · 81초**다. 게이트는 통과할 때 아무 말도 하지 않는다. 이것이 ②를 정상 통과와 **종료 코드·stdout 에서 구분 불가능**하게 만드는 배경이고, 세 사례를 개별로 고쳐도 남는다. 이 배경의 수리는 t41 이다.

> **[주의] 「바이트 단위로 같다」는 관측이 아니다 — 이 SPEC 은 그렇게 주장하지 않는다.**
> 실측된 두 실행의 stderr 는 **같지 않았다**: `gate-baseline.err` 0바이트 대 `gate-p3.err` **416바이트**(설정 경고).
> 「`.moai/config/sections` 가 있는 디렉터리였다면 stderr 도 0바이트였을 것」은 원 보고(`reproduction.md:84`)가
> **조건부로** 적은 미측정 추론이고, 그 조건은 재현된 적이 없다. 관측으로 선 것은 **종료 코드(둘 다 0)와
> stdout(둘 다 0바이트)의 동일함**뿐이다.

## 3. 요구사항 (GEARS)

### A — 검사 목록의 수리 (코드 편집이 있는 유일한 항목)

- **REQ-GATECHECKS-001** (Ubiquitous) — `server/package.json` 은 `pretest` 스크립트를 가져야 하며, 그 스크립트는 server 워크스페이스의 타입 검사를 수행한다.
- **REQ-GATECHECKS-002** (event-driven) — **When** `server` 트리에 타입 오류가 존재하는 상태에서 `moai gate` 가 실행되면, 게이트는 0 아닌 종료 코드를 낸다.
- **REQ-GATECHECKS-003** (event-driven) — **When** `server` 의 `pretest` 가 타입 오류로 실패하면, 실패 출력은 `tsc` 진단(`error TS` 형태)을 포함하여 **시험 실패와 구분 가능**해야 한다.
- **REQ-GATECHECKS-004** (Ubiquitous, 회귀 금지) — 타입 오류가 없는 트리에서 `moai gate` 는 RC=0 을 유지한다.
- **REQ-GATECHECKS-005** (unwanted) — `server` 의 `pretest` 는 빌드 산출물을 내보내지 **않아야 한다**(`shall not emit`). `channel` 의 `pretest: tsc` 는 `bin` 이 가리키는 `dist/` 를 만드는 **빌드**이지만 server 에는 빌드가 없다 — 문자 그대로의 모방은 쓸모없는 산출물을 만든다.
- **REQ-GATECHECKS-006** (Ubiquitous) — 게이트가 도는 타입 검사와 CI 가 도는 타입 검사(`.github/workflows/ci.yml:27`)는 **같은 명령을 참조**하여, 한쪽만 바뀌는 표류가 생기지 않아야 한다.

### B — 게이트 종료 코드 (범위 밖 · 요구사항 없음)

없다. §1 과 §7 을 보라.

### C — 명령 형식 교정 (편집 0줄로 종결)

- **REQ-GATECHECKS-007** (Ubiquitous) — 이 SPEC 은 C 항목이 **편집 0줄로 종결**되었음과 그 근거, 그리고 **닫히지 않은 잔여 위험**을 기록한다.
- **REQ-GATECHECKS-008** (unwanted) — 이 SPEC 의 실행은 `SPEC-PERMROUTE-001` 을 비롯한 어떤 **완결(`status: completed`) SPEC 의 본문도 편집하지 않아야 한다**.

### 서술 규율

- **REQ-GATECHECKS-009** (unwanted) — 이 SPEC 과 그 산출물은 **정의를 붙이지 않은 자리 수를 단독으로 서술하지 않아야 한다**. 같은 대상에 25 · 37 · 28 · 23 네 값이 나왔고(넷 다 서로 다른 질문에 답한다), 37 은 시점에 따라 46 으로도 나온다 — **검사 대상 값은 다섯이다**(§6).

## 4. C 의 종결 — 「닫지 않기로 정한」 종결

C 는 t34 감사 발견 H-01 이 권고한 **셸 무관 명령 형식**(`xargs grep … < list.txt`)으로의 교정이었다. **편집 0줄로 종결한다.** 근거 셋:

**① 완화는 이미 존재하고, 지시된 것보다 강하다.** 세 자리가 `[HARD]` 로 경고한다:

| 자리 | 내용 |
|---|---|
| `SPEC-PERMROUTE-001/spec.md:255` | `[HARD]` 「아래 명령의 `$F` 는 `bash` 의 무인용 단어 분리에 기댄다 … 재현은 `bash` 로 한다」 |
| `SPEC-PERMROUTE-001/progress.md:421` | `[HARD]` 「재현 시 셸 주의 … 재현은 `bash` 로 한다」 |
| `.moai/reports/t34/evidence/round4-section6-web-scope.txt:12-13` | 「[주의] … bash 로 돌릴 것」 |

**[정정] 셋째 자리의 경로는 `SPEC-PERMROUTE-001/evidence/` 가 아니다.** 카드 인계문과 재현 보고 §7 이 파일 이름만 적어(`evidence/round4-section6-web-scope.txt`) 앞 둘과 같은 디렉터리처럼 읽혔으나, `SPEC-PERMROUTE-001/` 에는 `evidence/` 디렉터리가 없다(`spec.md`·`plan.md`·`acceptance.md`·`progress.md` 넷뿐). 실제 위치는 **t34 보고서의 증거 디렉터리**다.

이 정정은 근거의 무게를 바꾼다. **앞 두 자리만이 SPEC-PERMROUTE-001 독자의 경로 위에 있다** — 표 직전(`spec.md:255`)과 표 직후(`progress.md:421`). 셋째는 t34 보고서를 읽는 사람의 경로이지, 재현 명령을 읽으러 온 사람이 반드시 지나는 자리가 아니다. 그래도 ①의 결론은 선다 — **재현 명령이 실린 두 표는 각각 바로 앞뒤에 `[HARD]` 경고를 달고 있다.**

**② 경고가 감사보다 하루 먼저 착지했다.** `git merge-base --is-ancestor c3d1d09 83c3078` → YES (경고 2026-09-03, 감사 발견 2026-09-04). 그런데 H-01 본문은 이 경고를 **한 번도 언급하지 않는다**(해당 구간 grep 계수 0).

**③ 따라서 H-01 자신이 미검증 전제 위에 선 권고다.** H-01 은 「다음 사람은 모든 어간에서 0 을 보고 「뒤집힌 자리가 없다」고 읽는다」고 적었으나, 문서는 그 두 줄 위에서 `[HARD]` 로 정확히 그 오독을 금지하고 있었다. `verification-claim-integrity.md` §1.1 surface 4(권고 전제 주장)에 해당한다.

**[HARD] 그러나 이것이 위험이 0 이라는 뜻은 아니다.** §5 를 보라 — 잔여 위험은 **열린 채로** 남는다.

## 5. 잔여 위험 (열림)

- **[열림] 지시에 의한 완화 ≠ 구성에 의한 완화.** 현재 경고는 「`bash` 로 돌려라」라는 **지시**이고, 복사·붙여넣기 하는 사람이 건너뛸 수 있다. H-01 이 처방한 셸 무관 명령 형식은 **건너뛸 수가 없다**. 이 차이는 실재하며 이 카드가 닫지 않는다. 닫으려면 완결 SPEC 의 본문을 편집해야 하고, 운영자가 그것을 배제했다.
- **[열림] plan 단계 최종 감사 점수는 이 트리를 잰 값이 아니다.** 2회차 계획 감사의 **0.800** 은
  커밋 `53fa29a` 에 귀속된다. 그 뒤의 `1fe923c`(차단 B-1r + 비차단 6건 교정 · AC-GATECHECKS-010
  신설)와 `d367db2` 의 변경은 **측정되지 않았다.** 감사관이 AC-GATECHECKS-010 신설로 추적성이
  1.00 이 되어 총점 0.842 가 된다고 산정했으나 그 또한 **미측정 추정**이다. 3회차를 돌리지 않는
  근거는 리드 처분 9 의 종료 규칙이다 — 「재감사는 점수가 귀속되지 않은 트리를 잰 경우에만 다시
  돈다. 감사가 스스로 지시한 교정을 이행한 것은 재감사 사유가 아니다.」 규칙은 타당하나 그것이
  **이 트리의 점수를 세워 주지는 않는다.** 열린 채로 둔다.
- **[기록] 과대주장의 채점 자리 — 운영자 처분 「현행 유지」.** 두 회차 모두 사실 과대주장(B-1 ·
  B-1r)을 **차단 발견으로** 다루고 명료성 점수에서는 깎지 않았다. 명료성에 접어 넣으면 총점
  0.706 · FAIL 이 되나, 운영자 판단은 **현행 유지**다: 과대주장은 문장이 모호해서가 아니라 사실이
  틀려서 생기며 완벽히 명료하면서도 틀릴 수 있으므로 명료성은 잘못된 자리다. t40 은 PASS 0.800
  으로 확정하고 1회차 소급 재채점은 없다. 4차원에 「사실 정확성」을 담을 자리가 없다는 루브릭
  공백 자체는 **별도 카드 t42** 로 분리됐다 — 이 카드에서 닫지 않는다.
- **[열림] §6 의 계수는 시점에 귀속되며 이 SPEC 은 그것을 고정하지 못한다.** §6 의 네 명령은 자기
  산출물을 훑기 범위에 포함하므로, 이 SPEC·보고서가 한 줄이라도 자라면 값이 움직인다(`46` 시점 대
  `53fa29a` 시점: 46→53 · 28→32 · 차이 18→21). §6 은 각 수에 시점을 붙여 기록할 뿐이고, **자기 제외
  훑기로 값을 고정하는 일은 이 카드가 하지 않는다** — C 가 편집 0줄 종결이라 이 수는 행동의 분모가
  아니기 때문이다. 시점 없이 인용하면 거짓이 된다.
- **[열림] 통과의 침묵.** 게이트는 통과 시 0바이트를 낸다. A 를 착지시켜도 「다 돌고 통과」와 「돌 게 없어 통과」는 겉으로 같다. → t41.
- **[미검증] 다른 언어 프로젝트에서 게이트가 무엇을 도는지** 재지 않았다. §2 의 「단계는 하나뿐」은 **이 저장소 한정** 관측이다.
- **[미검증] `disabled_steps: {}` 인데도 lint 단계가 안 보이는 이유** 를 규명하지 않았다. eslint 설정 부재로 건너뛴 것인지, JS 툴체인에 lint 단계가 애초에 없는 것인지 갈리지 않았다.
- **[미검증] `--passWithNoTests` 가 만드는 네 번째 조용한 초록**(시험 0건 워크스페이스)은 재현하지 않았다. **이 카드 범위 밖**이며 t41 에 후보로만 있다. 덧붙여 이 회차의 별개 관측 — 장난감 워크스페이스에서 같은 명령을 돌리자 npm 이 `npm warn Unknown cli config "--passWithNoTests"` 를 냈다. 그 플래그가 워크스페이스 스크립트까지 실제로 전달되는지는 **재지 않았다**.
- **[미검증] t39 M6 1차의 원 스크립트**를 직접 돌리지 않았다. 사례 ②는 `cd .moai` 로 **합성 재현**했다.

## 6. 계수 규율 — 「37자리」를 단독으로 쓰지 않는 이유

같은 대상에 네 값이 나왔다. **어느 하나도 「맞는 수」가 아니다** — 넷이 서로 다른 질문에 답한다.

|---|---|---|

> **[주의] 이 아홉은 아래 분해표의 원인 ①(=7)이 아니다.** 둘은 **다른 시점의 다른 집합**이다:
