경쟁 가설 여럿을 「무엇을 보면 갈라지는가」로 가르는 SPEC 에서, 판별 규칙이 **순수 함수로는 옳고 정의역으로는 죽어 있는** 경우를 의심한다. 기준이 합성 입력만 쓰면 이 죽음이 보이지 않는다.

**Why:** t39(SPEC-WSUPGRADE-001)의 2차 판정표가 세 갈래를 「원격 포트 = 자기 포트?」와 「주소 계열 일치?」로 갈랐다. 둘 다 실물에서 상수였다 — 클라이언트가 자기 포트를 직접 걸므로 `remotePort` 는 TCP 정의상 언제나 자기 포트와 같고(H-1 도달 불가), 리터럴 `127.0.0.1` 로 걸면 소켓은 언제나 IPv4 인데 `listen({port:0})` 한 Fastify 의 `address().family` 는 언제나 IPv6 이라 계열은 언제나 불일치했다. 진짜 오배선을 강제로 만들어 재현했더니 표는 H-1 을 H-2 라고 답했고, 경합이 전혀 없는 정상 케이스(H-3)도 **같은 두 입력**을 냈다. 셋이 한 점으로 붕괴했는데 수용 기준은 「세 가지 합성 입력이 세 이름을 내면 통과」였고 계획은 「합성 입력만 쓴다」고 못 박았다. 기준은 초록으로 통과했을 것이다.

**How to apply:** 판별 규칙을 만나면 각 분기마다 **그 분기를 내는 입력이 실물에서 어떻게 생기는가**를 한 줄로 말해 본다. 말할 수 없으면 그 분기는 죽었다. 특히 관측 지점이 클라이언트 소켓이면, 클라이언트가 스스로 정한 값(건 주소·건 포트)은 판별에 쓸 수 없다 — 자기가 쓴 값을 자기가 되읽는 항등이다. 확인은 탐침 한 줄이면 된다(정상 케이스 한 번 + 결함을 강제한 케이스 한 번, 두 출력이 다른가). 수정 방향은 소켓 튜플이 아니라 **응답자 신원**(자기 앱이 그 요청을 실제로 받았는가)으로 옮기는 것.

같은 뿌리의 형제: [[spec-criteria-that-verify-nothing]], [[mutation-that-deletes-its-own-judge]], [[criterion-rogue-weaker-than-real-attacker]] — 셋 다 「기준이 무언가를 재기는 하는데 재려던 것을 재지 않는다」이고, 이 항목은 그중 **정의역이 비어 있는** 갈래다.
