부류 결함을 고쳤다는 개정을 검증할 때, **그 라운드가 새로 더한 자리**를 옛 자리와 따로 재라. 처방은 기존 행에만 적용되고 신설 행은 처방 이전 형태로 태어난다.

**Why**: t6 3회차. 「측정이 자기를 센다」(N-02)를 닫으라 했더니 개정자가 `spec.md` §7.3 훑기 표의 **값 축 네 행**을 `grep '^- 측정' … | grep -c …` 로 좁혔다 — 정확한 처방이고, 머리말에 `[HARD] 원시 개수로 못박지 않는다` 까지 세웠다. 그런데 **같은 라운드가 새로 더한 명제 축 두 행**은 원시 파일 개수 그대로였고, 그중 하나(`종결 정의|종결 조건` → 못박은 3, 실측 **6**)는 적중 여섯 중 **셋이 표 자신**이라 도착 즉시 거짓이었다. 개정자는 §6 에 「나도 같은 함정을 한 번 더 밟았다」고 **자진 신고까지 했는데도** 신고한 그 축이 안 고쳐져 있었다. 자진 신고는 정직함의 증거이지 수정의 증거가 아니다.

같은 라운드에서 P-02 도 나왔다: 행1 이 `grep -rn '/13\]' .` → `0` 이라 적었으나 나무 전체로 돌리면 **17**(감사 보고서·다른 카드 산출물에서 적중). 값은 SPEC 디렉터리로 좁혔을 때만 참 — 「실행하지 않은 명령을 인용했다」의 재현.

**How to apply**: 개정 검증 시 (1) 처방이 적용된 행과 **신설된 행**을 목록으로 갈라라, (2) 신설 행마다 적힌 명령을 **적힌 형태 그대로** 돌려 적힌 값이 나오는지 봐라 — 범위(`.` vs 특정 디렉터리)가 특히 자주 어긋난다, (3) 표 행이 자기 어간을 포함하는지 확인하고 자기 제외가 **명령 안에** 있는지 봐라. 산문 괄호의 「이 문서 제외」는 명령이 아니다.
