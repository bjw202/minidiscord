수용 기준의 증거가 **형제 SPEC 이 이미 만족시키는 관측물**이면, 그 기준은 이 SPEC 이 더하는 것을 재지 않는다.

t32(`SPEC-LIVEVERIFY-001`)에서: 형제 `SPEC-E2E-001` 이 **가짜 채널**(평범한 WebSocket 클라이언트)로 같은 흐름을 자동 검증해 이미 닫혀 있었고, 이 SPEC 의 존재 이유는 오직 「봇이 **진짜 Claude Code 세션**이다」 하나였다. `spec.md` §7 이 그 경계를 스스로 적는다 — 「경계는 **누가 봇인가**다」. 그런데 AC-001 의 증거는 브라우저 화면의 `🟢 pm` 칩 한 장이고, 그 칩은 게이트웨이에 붙은 것이 무엇이든 글자 하나 다르지 않게 뜬다. 열두 항 어디에도 세션 쪽 터미널 아티팩트가 필수로 걸리지 않았다(있는 것은 `/clear` 를 보이는 부속 캡처 하나).

**Why:** 수동 수용 SPEC 은 「관측 대상을 화면 모양으로 적어라」를 지키면 잘 쓴 것처럼 보인다. t32 는 그 규약을 §3.2 에 명문화하고 대부분의 기준에서 지켰다 — 그래서 더 안 보인다. 규약은 *각 항이 무엇을 보이는가*만 강제하고, *이 SPEC 전체가 무엇을 새로 보이는가*는 강제하지 않기 때문이다. 기준을 한 줄씩 읽으면 전부 통과한다.

**How to apply:** 형제·선행 SPEC 이 있는 카드를 감사할 때, 개별 기준을 보기 전에 먼저 한 문장을 세운다 — 「이 SPEC 이 형제와 갈리는 지점은 X 다」(대개 SPEC 자신의 범위 밖 절에 적혀 있다). 그다음 **X 를 관측하는 기준이 하나라도 있는지**만 따로 훑는다. 없으면 차단이다. 판별식: 「형제의 산출물을 그대로 돌려도 이 증거 파일들이 똑같이 나오는가?」 — 그렇다면 증거가 경계를 못 가른다.
