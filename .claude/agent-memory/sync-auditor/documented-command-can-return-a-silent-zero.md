SPEC·보고서에 **재현 명령**이 실려 있으면, 그 명령을 **실린 형태 그대로** 한 번 돌려 본다.
값을 얻으려고 「동작하는 형태」로 고쳐 돌리면, **문서의 명령이 재현 불가능하다는 사실 자체를
놓친다.**

**Why:** t34 3회차 — SPEC §6.1 이 대표 훑기의 재현 명령을
`F=$(cat scope-ex-self.txt)` + `grep -n -- '<어간>' $F | wc -l` 로 싣고 있었다. 이 프로젝트의
기본 셸은 zsh 인데 **zsh 는 따옴표 없는 매개변수 확장을 낱말 분리하지 않는다** — 116개 경로가
파일 이름 **하나**로 넘어가 어간마다 `0` 이 나온다. 종료 코드는 `0`, 출력은 비어 있고, 경고는
`ugrep: warning:` 로 stderr 에만 뜬다(흔히 `2>/dev/null` 로 가려진다). bash 에서는 정상값 32 다.

곧 **「뒤집힌 자리 0건」이라는 통과 판정이 명령이 아무 파일도 읽지 못해서 나온다.** 「신호의
부재는 통과가 아니다」의 가장 조용한 형태이고, 하필 그 규율을 세우려는 SPEC 안에 있었다.

**How to apply:**
- 문서가 명령을 싣거든 **그 형태 그대로** 먼저 돌린다. 값이 필요하면 그 다음에 고친 형태로
  다시 돌리고, **두 결과가 다르면 그것이 발견이다.**
- `0` 을 받으면 그것이 「없다」인지 「못 읽었다」인지 가른다. `wc -l` 앞의 명령을 `2>&1` 로
  다시 돌려 stderr 를 본다 — 파이프와 `2>/dev/null` 이 가장 흔한 은폐 경로다.
- 파일 목록을 명령에 넘길 때 `$F` 확장에 기대지 말고 `xargs <cmd> < list.txt` 를 권고한다.
  셸에 무관하고 인자 길이 상한도 넘긴다.
- 이 부류는 **선재**이기 쉽다(명령 형식은 대개 오래됐다). 차단으로 올리기 전에
  `git show <HEAD>:<file> | grep -cF '<명령 형식>'` 으로 선재 여부를 확인한다.
